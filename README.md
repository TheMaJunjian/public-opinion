# 公论

以消息推进会议，通过举证、表态、组织讨论和结算形成可继续质疑的共识。

功能依据：[第一版规范](docs/公论第一版规范.md)。

## 运行

需要 Node.js 24 或更新版本，以及已启动的 Docker。首次运行时将 `.env.example` 复制为 `.env`；已有 `.env` 则保留并配置其中的 `DATABASE_URL`。在仓库根目录运行：

```sh
npm ci
npm run dev
```

访问 http://localhost:5173。开发代理与后端保持同源请求；后端监听 3000。开发脚本自动启动 PostgreSQL 16，数据库只向本机开放 54329 端口，数据保存在 Docker 卷 `gonglun-dev_postgres_data` 中。

已有 PostgreSQL 时，在根目录 `.env` 或环境变量中设置 `DATABASE_URL`，开发脚本会直接连接该数据库。变量示例见 [.env.example](.env.example)。首次连接时自动建立表，不导入旧数据库数据。

```sh
npm test
npm run build
npm start
```

构建后由同一个服务提供页面和 API。部署配置见 [部署说明](README/云服务器部署.md)。

## 代码

- `frontend`：保留来源、目标、文本选择和发送操作的工作台；部件引用、非线性显示、增量同步。
- `apps/server`：消息命令、权限、事务账本、结算和快照接口。
- `packages/core`：消息及引用模型、规则、布局协议、执行记录和导出复算。

分类、总结、归并和排列均为消息；主页是查询视图。一次发送的多个操作通过一个事务提交。同步按执行序号补齐变更，界面显示取决于消息关系与已生效状态。

新建容器时，每个成员都会生成独立的加入消息，和容器一起原子提交，附属加入记录不另收协议费。追加成员使用同一种加入消息；每条记录保存此前生效的归属依据，一个消息最多只有一条生效的加入记录，位于根层时可以没有。移出成员通过反对其生效加入消息完成；反对容器时沿成员各自的归属历史恢复位置，跳过已失效的加入记录和容器，保留之后仍有效的独立移动。列表中的“移出容器”会将对应加入消息选为反对目标，发送后生效。

消息上的“加入”标签查看该消息加入容器的全部记录；容器上的“被加入”标签查看成员加入该容器的全部记录。嵌套容器同时具有两种入口，图与列表保持一致；记录页包含生效及未生效的历史消息，退出后恢复原筛选和预览。
