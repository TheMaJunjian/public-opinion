# 公论

公论是争论、辩论和线上文字开会的工具：讨论、投票、结算，让争论有结果。

公论中有：发言投票（权），胜利的一方获得贡献点（钱），给所有人留下被认可的信息（真理）。

贡献点是对公论贡献的计量。使用、判断、举证、开发、设计、推广、运营和资金支持，都应进入公开的贡献记录与认定过程。**用公论运营公论：一切运营由公论用户负责，所有运营信息在公论上公开。**招合伙人，条件不限；线上运营，信息公开；投票结算，按功分配。欢迎加入楚门计划。

公开透明是组织原则。当前系统中心化运行，透明中心与去中心化方案仍在比较，按成本、效率和可核验程度选择，不把上链或多节点预设为必经路线。

## 邀请注册与账号管理

新用户须使用管理员生成的一次性邀请码注册。现有创始用户担任管理员，登录后从导航栏“管理”进入：在“邀请码”页生成、查看使用状态或撤销邀请码，在“账号”页搜索并停用、恢复普通账号。邀请码默认 7 天有效，可选择 1 至 365 天；完整代码只在生成时显示，需及时复制保存。数据库只存摘要，邀请码及管理记录不进入公开消息和导出。

邀请码由服务端校验，过期、撤销或已经使用的代码不能注册。核销与创建账号在同一事务中完成，注册失败不消耗邀请码，多设备同时使用只允许一个账号成功。新站点的首位管理员沿用初始发起人密钥流程，不需要邀请码。

停用会清除该账号的全部登录会话，禁止再次登录和业务写入，并停止使用贡献计时；已打开网页在下一次鉴权请求时退出登录。历史消息、已有余额及账本保留。恢复后须重新登录，旧会话不会恢复。管理员不能停用自己或其他管理员。公开内容的游客阅览规则保持不变。

数据库版本 35 新增独立的邀请、账号停用及管理操作记录表。升级自动执行，已有账号默认保持可用，原有账号、密码、会话和账本不变；升级后新增普通账号必须持有邀请码。

## 贡献点计时规则

注册账户从 0 点开始。每天第 1 点需等待 1 秒，第 2 点等待 2 秒，依次递增；只要公论网页保持运行，每轮计时完成就自动领取 1 点并开始下一轮，不需要点击、按键或滚动。后台继续计时，关闭页面后停止自动领取。进度按账号保存在服务端，刷新页面、重新登录和打开多个页面不会重置或加速计时。请求失败会自动重试，重复请求和多页面竞争不会重复发放。

每天北京时间 00:00，上一天未领取的那一轮无论是否等满，都自动补发 1 点，等待进度及当日递增次数清零，下一轮从 1 秒开始，已有贡献点保留。离线多天只补发离开前正在等待的那一轮；服务重启后会补办未完成的刷新。导航栏使用安静的进度条显示本轮进度，不显示操作提醒。

版本 29 将后续使用贡献改为每人每天一条累计账目、一条发放消息和一个正文版本，普通领取与零点补发累计至实际发放日。同日继续领取只更新当天合计，执行历史保存简短的金额增量及累计值，完整导出仍可复算。升级不清零已有贡献点，也不改写既有流水。贡献点一级面板按一次操作汇总后分页并倒序显示：一次发送产生的文本、引用关系及附属消息，其协议费、自押、审核报酬预留和审核自押归入同一条记录，显示净增减、可用余额前后值、锁定变化及所有关联消息。点击“详情”打开二级窗口，汇总本次操作的收入、支出和净变化，并按时间倒序列出每笔金额、余额及对应消息，不受一级分页限制。重复请求不会新增操作记录，新的发送分别记录；审核、结算等后续操作各自形成记录。使用贡献在一级和二级均按北京时间日期汇总，不拆成每次领取，详情显示日期、累计获得、发放次数、最近记录及关联消息。审核隐藏正文时仍保留各笔金额和关联消息跳转；使用贡献汇总行不冒充单笔收支的余额。版本 30 将现有汇总消息的名称统一为“使用贡献”，不改变余额或原始历史。

版本 44 将操作分组保存在独立的账本关联表。升级时按历史发送批次、请求回执和执行记录恢复可核实的操作边界；不能确定归属的旧流水仍独立展示，不按时间接近程度猜测合并。迁移不修改账户、原始流水、签名或执行历史，恢复后的备份数据库同样可升级，重复执行不重复归组。

数据库版本 27 在切换规则前逐行归档旧账户、流水、押注、结算、委托资金、消息、版本、执行历史及消息图关系，并核对归档与原数据完全一致，保存各表数量和 SHA-256 摘要。校验通过后清零旧账户和运营余额，取消旧押注及委托资金的后续结算，当前消息上的旧投入归零；消息正文、编号和图关系保留。失败时归档和清零一并回滚，重复升级不重复清零。旧流水和执行历史保留供审计，新余额及收支展示从切换点开始。

版本 31 对清零前仍保留的应付费用户消息补记新版最低消耗：每条投入 1 点并支付当前协议费，允许余额变负，后续使用或充值所得先抵扣欠额。系统生成的免费记录不补扣，切换后的新消息不重复收费。协议费及普通价值投入计入运营资金，真假与标注投入建立新的押注和结算记录，不恢复旧充值、旧资金池或旧结算结果，也不重新执行消息操作。每条补扣留有记录，重复升级不重复扣款。排行榜保留旧消息，按补扣后的实际投入重新统计；充值贡献和累计使用贡献分别读取清零后的账号累计值，自动发点记录不计消息数。

版本 28 将早期计时表升级为每日零点刷新规则，保留已有新贡献点和当时正在等待的一轮；旧计时记录先备份，再转换。此前只有数量清单的旧贡献点存档会核对数量并补充 SHA-256 摘要，不重新清零账户。

查看或导出旧贡献点存档：

```sh
npm run db:points-archive -- --list
npm run db:points-archive -- 旧贡献点存档.json
```

导出可在路径后追加归档编号；导出前核对各表数量和摘要，不覆盖已有文件。部署构建后可用 `node --env-file-if-exists=.env apps/migrate/dist/points-archive-cli.js 输出.json`。

本机文件阅览仅作为辅助，公论的主要功能仍是消息与讨论。知乎导出文件的本地阅览、整理和增量更新用法见 [本地文件阅览](docs/本地文件阅览.md)。

更正与版本的统一设计及实现差异见：[消息更正、正文版本、已阅与影响归属规则](docs/消息更正与正文版本规则.md)（当前简化规则）。

## 内容审核

消息卡的审核统计位于真假、价值入口左侧：点击通过、不通过数字进入同一审核汇总临时分类，右侧盾牌按钮打开审核仲裁面板，与真假、价值仲裁采用相同的面板方式。审核记录依附目标，不单独出现在主消息流中。发送审核成功后自动进入目标的审核汇总临时分类。临时分类默认同时汇总通过和不通过的理由，按本轮每人最新判断统计，不提供立场筛选。被审核消息始终显示，可切换消息图、消息表；原始记录默认收起，展开或收起只影响审核记录。理由旁可赞同、反对，准备对应的新审核消息，确认押注后发送。“运营 → 附加关系 → 审核”也可选择通过、不通过并填写可选理由；默认附加关系为公告。审核消息依赖被审核消息，理由保存在这条关系消息内，不另建正文。导航栏“审核”显示自己的内容和随机分配的任务，也可选择是否参与随机审核。已登录且能阅读对应消息版本就能审核，包括作者，无需随机分配；管理员没有全局查看特权。审核、复核、随机任务分配与收回、结算和资金划转均保留关系消息记录；审核理由可以留空，复核理由必填。

普通文本、网页、代码、提案、运营公告，以及带用户正文的总结、分类、委托和正文更正需要审核；自定义标签独立审核。纯结构关系、宽度调整和审核理由免审。内容发布即公开，待审不影响阅读。审核结算不通过后以占位卡替代，相关引用摘录一并隐藏，任何人都不能再把它或依赖它的受限引用作为普通消息的来源或目标。结算确认后立即分配审核资金，不通过的正文仅作者可见。个人投“不通过”后，本人默认看到遮罩，可展开正文并重新遮挡，不改变公开审核结论。申请复核后仅作者和新一轮随机审核者可见，旧轮次任务和临时阅读权限失效。已存在的相关记录和资金保留。

审核与真假、价值仲裁一样，按双方累计押注点数决定结果，发布自押、复核自押和旧轮次保留的押注均计入对应立场；投入较大的一方胜出，平局为未定（UNKNOWN），退还双方押注本金。审核人数和复核轮数不影响胜负，不设最低人数门槛，也不逐级扩审。随机任务默认同时分配 3 人，提供邀请、临时阅读权限和本轮结算资格；有效任务接收者无需先提交判断，也可按已有押注结算，但作者不能结算自己的内容。系统从当前在线、账号正常、参与随机审核且可用点足够支付协议费和最低押注的用户中抽取，排除作者。登录或前台心跳后 2 分钟内视为在线；前台页面每 30 秒发送心跳，后台轮询不延长在线状态，仅有未过期登录会话不算在线。离线后不再接收新任务，已有随机任务默认 30 分钟有效；未提交者超时只收回此条消息本轮的任务及临时阅读权限，再从在线用户中随机补位，公开内容仍可阅读和审核；已提交审核者在本轮结算前保留阅读与审核权限。每次复核期间累计随机分配上限默认为 6 人，同一轮不重新抽中已失效者；候选人不足时等待补位，不自动通过。

默认每个内容版本冻结审核费 6 点和审核通过自押 10 点，最低审核押注 2 点，另付协议费；审核资金与真假、价值分开记账。自押计入对应立场的资金总额和结算权重，不占随机审核名额，也不领取参与报酬。每轮前 3 名不同的有效审核者各获得 2 点参与报酬，不以判断胜负为条件，重复提交不重复领取，未使用预算退付款人。后续审核者仍可按押注比例取得反方错误押注。作者可另行提交审核，但不能结算自己的内容；自押计入审核权重。确认审核结算时立即划转资金，不再设置异议等待期或二次划转操作；结算后改变结论须付费申请复核。自押与审核押注共同结算，与最终结论一致的一方按投入比例取回本金并分享反方押注。

每次复核须支付新一轮审核费 6 点、追加自押 10 点及协议费 1 点，合计 17 点，新增费用须有足够可用点。复核自押支持所申请的相反结论：作者申诉“不通过”时押通过，质疑“已通过”时押不通过；未定结论可选择复核自押方向，提交前显示立场。复核冲正先前押注与自押分配并重新锁定，已发放参与报酬保留；旧轮次资金保留原立场，继续计入结算权重和最终分配。奖励名额、单人报酬、最低押注和复核费用均为规则参数，后续可调整。

数据库版本 36 将旧内容一并纳入审核，按当前规则逐条扣减可用点并冻结审核费、保证金，余额不足记欠额。迁移与版本登记在同一事务完成，重复运行不重复扣费；真假、价值资金保持原账。每个版本保留审核快照，批准新版不会自动公开未通过审核的旧版。启用审核后的网页导出是当前可见视图，完整私有正文、签名请求正文及审计历史不进入公开导出。

数据库版本 43 切换为按累计押注点数进行审核仲裁。通过 `npm run db:migrate` 升级后，旧规则下尚未划转资金的暂定结论重新待结算，扩审级别清零；原押注、自押、审核费、参与报酬以及已完成的资金分配保留，升级不扣费、不划转资金。

数据库版本 37 为已经执行早期审核迁移的数据库补齐引用版本字段，并从消息历史重建审核引用索引；该修复不重新扣费，也不改变余额或账本。

数据库版本 38 将固定审核资格改为按消息随机分级分配。未完成且已有旧投票的审核开启新轮次，原投票、押注及已完成结算保留；迁移不重复收费，不改变余额和账本。

数据库版本 39 增加会话最近在线时间。旧会话默认离线，等待前台页面重新发送心跳；不改变登录凭证、已有审核资格和资金记录。

数据库版本 40 改为内容先公开、否决后隐藏，并增加分轮审核费和累计保证金记录。原余额、账本及已冻结金额保持不变，不补扣费用；旧预算仅发放其足以支付的完整奖励名额，剩余返还付款人。尚无人提交但已分配过资格的旧待审内容开启新轮次重新抽人，原资格记录保留；已有押注的轮次保持原样。

数据库版本 41 为历史“纳入审核”记录补齐被审核消息及其当时版本的依赖关系，仅在对应消息的审核临时分类中显示。修复保留记录编号与原始历史，通过新版本发布；不重复纳入审核，不改变余额或账本。后续历史内容迁移直接生成带目标的审核记录。

数据库版本 42 将已有保证金原额转为带立场的审核自押：发布自押为通过，旧复核自押从当时的审核结论恢复相反立场。迁移不扣款、不改变余额与账本、不重新分配已完成的结算；后续复核仍可冲正旧分配并按新规则结算。转换记录依附对应消息版本，只在审核临时分类中展示；缺少可确认的复核历史时整批回滚。

## 运行

需要 Node.js 24 或更新版本，以及已启动的 Docker。首次运行时将 `.env.example` 复制为 `.env`；已有 `.env` 则保留并配置其中的 `DATABASE_URL`。在仓库根目录运行：

```sh
npm ci
npm run dev
```

访问 http://localhost:5173。开发代理与后端保持同源请求；后端监听 3000。开发脚本自动启动 PostgreSQL 16，数据库只向本机开放 54329 端口，数据保存在 Docker 卷 `gonglun-dev_postgres_data` 中。

已有 PostgreSQL 时，在根目录 `.env` 或环境变量中设置 `DATABASE_URL`，开发脚本会直接连接该数据库。变量示例见 [.env.example](.env.example)。首次连接时自动建立表，不导入旧数据库数据。

### 雷电模拟器测试

Windows 下双击仓库根目录的 `start-android.cmd`，或桌面的“公论手机测试”快捷方式。它会自动启动缺少的开发服务、启动雷电、等待安卓就绪、建立端口连接，并在雷电的 Chrome 中打开测试页面。已有服务和模拟器会直接复用；重复双击可恢复模拟器重启后丢失的连接。开发服务在后台运行，启动日志保存在 `artifacts/android-dev/`。需要本地数据库时会尝试启动已安装的 Docker Desktop。

也可以在仓库根目录运行同一个一键启动流程：

```sh
npm run dev:android
```

测试地址为 http://localhost:5173/messages，即可测试注册、登录和发送消息。端口通过 ADB 连接电脑；浏览器把 `localhost` 视为安全上下文，因此支持 WebCrypto，无需配置 HTTPS 或开放防火墙。

首次使用时，在雷电设置 → 其他设置 → ADB 调试中开启本地连接。脚本优先选择雷电14，自动查找常见安装位置；可通过 `LDPLAYER_HOME` 指定包含 `ldconsole.exe` 和 `adb.exe` 的目录，`LDPLAYER_INDEX` 指定实例编号（默认 0）。也可通过 `ADB_PATH` 指向同一安装目录的 `adb.exe`，通过 `ANDROID_SERIAL` 或 `npm run dev:android -- emulator-5554` 指定连接编号。

```sh
npm test
npm run build
npm start
```

构建后由同一个服务提供页面和 API。部署配置见 [部署说明](README/云服务器部署.md)。

数据库启动时自动检查版本；发现旧库后调用独立程序 `apps/migrate` 完成升级，再启动服务，不显示迁移提醒或要求确认。迁移逻辑仍与业务程序分离。需要单独预检或维护时可执行：

```sh
npm run db:migrate -- --plan
npm run db:migrate
npm run db:verify
```

迁移在跨进程事务锁内按版本执行，失败整体回滚，已完成版本不再执行。升级前后逐行校验账户与账本，转换前原文保存在迁移备份表；消息编号、引用位置、签名原文和资金记录保留。空库由主程序直接建立最新版表结构。

成功转换保持静默。失败时，网页与启动日志会明确显示失败时间、原因和回滚结果，刷新页面仍可查看；业务接口与健康检查返回 503，部署命令会输出失败报告并退出失败。原生数据库转换在事务内回滚；旧 Prisma 导入保留原库、不切换失败结果，并清理本次临时转换数据。连接中断、提交结果不明确或清理失败时，会显示“无法确认”或具体清理失败信息，不误报已回滚。修复原因后重新启动即可再次尝试。

旧 Prisma 数据库会自动导入同库的独立 schema，通常为原 schema 加 `_gonglun_2`，成功后切换本次服务连接；原 schema 完整保留。后续启动识别已完成的导入，不重复复制。默认将最早注册的旧用户设为创始用户，也可预先配置 `GONGLUN_LEGACY_FOUNDER_ID`。原有活动本金须与账户锁定额完全一致，转换不增发、清零或强制结算；零投入消息另按下述最低投入规则补扣。未知版本、损坏引用或资金不一致时保留原数据并停止启动。

旧消息格式、历史资金查询记录、隐式组织归属和关注／拉黑的“是／否”理由均由迁移程序一次性转换。旧阅览 JSON 在选择文件、打开历史缓存、进行增量更新时自动在本机转换，原磁盘文件不变，不增加转换确认。也可使用 `npm run db:migrate-view -- 输入.json 输出.json` 或构建后的 `/migration/` 手动另存新版文件。文件和数据库共用格式转换函数；转换过程不发送消息或重新执行资金操作。

JSON 转换或校验失败会在当前窗口显示失败时间、原因与原文件／缓存的保留结果；缓存读取失败、缓存缺失或损坏也会明确提示。转换与校验全部通过之前不会保存转换结果，失败后仍可重新选择原 JSON 文件。

支持早期分开保存正文与关系的导出、原生完整执行记录及旧经济审计 JSON。经济审计原文保存在 `sourceAudit`，没有新版完整账本时不声称通过资金复算；缺少分页记录的执行日志会返回错误，不猜测补齐。

更新迁移代码时应新增数据库版本，不能只修改已经执行过的步骤。版本 7 会补齐此前版本缺少的消息格式和个人推荐标记；旧库下次启动自动执行，重复启动不追加变更。

版本 11 要求每条用户发送的消息在“真假”和“价值”中至少有一项大于 0，可以同时投入；协议费另计。工作台先显示真假，再显示价值。历史上两项都为 0 的用户消息各补 1 点真假自赞，从作者可用余额转入真实押注，余额不足时允许扣成负数。迁移保留原消息备份、原签名与既有流水，追加补扣账本及执行记录，不重放原消息的授权、转账或组织操作。系统生成的结算、分配和附属加入记录不另补扣。迁移在事务内执行，失败全部回滚，重启不重复扣点。

版本 12 排除旧版导入时记在用户名下的自动结算、分配记录；若它们已执行版本 11 补扣，则退回对应的未结算本金，保留原补扣及退款流水，重复升级不重复退款。

版本 13 的“已有旧押注即免补扣”规则已取消：后来追加的押注不能抵掉发送时的零投入。

版本 14 为新增的真假本金开放对应的整条消息结算地址，保留旧部件的资金边界，避免补扣后本金无法参与结算。

版本 15 按发送时的投入记录执行最低投入要求：发送记录中真假、价值均为 0 的用户消息都补 1 点真假自赞，后续追加押注不豁免。若此前因旧押注误退款，则补回这一点，原补扣、退款、重新补扣的账本和备份全部保留。

版本 16 通过独立迁移一次性删除附属关系消息对应的旧加入消息，退回实际收取的协议费、价值投入及押注本金；已结算的分配按原账本冲回，避免重复返还。更正、引用等原消息保留，旧版本和退款流水供审计与完整导出重放使用。迁移失败全部回滚，重复执行不重复删除或退款。可先运行 `npm run db:migrate -- --plan` 查看待删除记录，再执行 `npm run db:migrate`。

版本 17 将旧“创建委托／完成委托”消息中自动生成的“建立关系：DELEGATION”正文替换为当时保存的实际委托内容或完成说明，保持消息和正文部件编号、引用、签名输入及资金记录。原文先备份，再同步转换修订历史、执行记录与重试结果；已升级数据库在下次启动时补齐，旧离线文件使用相同转换。手写说明和缺少已保存正文的记录保持原文。

版本 3 取消旧 Topic 迁移产生的分类，将升级时仍直接属于它的成员放回根目录；已移出的消息、内部容器、原消息和历史记录保留。升级事件进入完整导出并可复算，生产预检、冲突规则及核验步骤见 [旧 Topic 分类增量升级](README/旧Topic分类增量升级.md)。

## 代码

站内通知位于导航栏账户区域，按与我相关、关注动态、资金与委托筛选。通知在业务事务中保存，取消关注只停止后续动态，已有记录保留；列表按消息类型分区，同类型多条默认折叠，显示已加载的条数和未查看数，可展开逐条查看。分区及区内通知按最新事件排序，加载更多保留手动展开状态。角标统计未查看事件数，展开列表不自动清除，定位成功后仅确认所点击的通知；全部已查看以列表快照为界，不覆盖同时到来的新通知。支持单条删除和按当前分类清除已查看通知，删除仅隐藏个人通知并保留去重记录，原消息、正文已阅、影响确认和资金记录不变。讨论可单独静音，实际影响本人资金的结果仍保留通知；自动使用贡献不产生通知。

数据库版本 32 新增私人通知及静音设置，旧明确通知回执作为已查看历史导入，不根据当前关注关系推测历史接收人。新事件使用现有 SSE 唤醒并由登录后的接口读取；恢复网络、返回页面及每 30 秒检查补齐数据和其他设备的查看状态。通知面板按需加载，跳转沿用工作台定位并保留草稿及地址中的筛选条件；目标已经位于当前可视区域时只显示定位提示，保持当前分类、追踪、视图和滚动位置。汇总或关联消息入口可见时，原位打开窗口并标绿对应记录，目标不在窗口首批记录中时自动显示到目标行；仅滚动窗口内部，不展开原始连线或滚动画布。

审核与任务撤回在通知内分区筛选，分别统计未查看数；已撤回、过期或轮次结束的未提交原任务也归入撤回区，在全部通知中与有效任务分组。审核另显示未处理数，支持“仅未查看”和“仅未处理”独立或组合筛选。处理状态按通知对应版本和审核轮次的实际任务计算，查看通知不代表提交审核；撤回、过期、已提交或已结束轮次均不计入未处理。批量清除已查看通知保留未处理审核，单独删除通知只隐藏提醒，不结束实际任务，仍可从审核队列进入。历史通知读取原始事件恢复轮次，不改写已有查看状态。

直接提醒包括他人对自己消息的回复、引用、注释、证据、更正、修改、赞同、反对、推荐、明确通知、委托完成与结算截止，以及正文版本更新；关注动态覆盖所关注消息和分类中的讨论；资金通知覆盖实际影响本人贡献点的结算、分配、调整和发放。加入记录新增时通知来源容器创建者和目标成员消息作者，失效或恢复时还通知加入记录作者；按实际有效状态变化去重，未改变归属的重复表态不产生额外状态提醒，操作人不通知自己。新成员通知定位成员正文，状态变化通知定位加入记录；回复等关系消息的滚动与蒙版中心均定位具体标签。版本 33 支持通知删除，版本 34 建立加入状态基线，旧加入记录不补发提醒。

- `frontend`：保留来源、目标、文本选择和发送操作的工作台；部件引用、非线性显示、增量同步。
- `apps/server`：最新版消息命令、权限、事务账本、结算和快照接口。
- `apps/migrate`：独立数据库迁移、旧库导入、旧文件与缓存转换、迁移核验工具。
- `packages/core`：消息及引用模型、规则、布局协议、执行记录和导出复算。

界面传输类型集中在 `packages/core/src/workbench.ts`，服务端投影与前端共用；绘图模型留在前端。工作台草稿及选择由 `useWorkbenchComposer` 管理，在线与离线数据投影由 `useWorkbenchRecords` 原子替换。发送失败可恢复草稿及临时数据，但不会覆盖发送期间收到的更新快照。

批量命令先持久保存幂等结果，再在独立只读事务中生成界面快照；投影失败可通过后续同步恢复。增量响应仅补齐相关用户及状态，空数组表示清除关注记录。数据库游标允许回滚产生空缺；变更通过 `previousSequence` 关联上一条已提交记录，导出另带记录数量及末尾游标清单，用于检查中间缺失和尾部截断。打开旧连续序号导出时自动补齐游标，缺少记录时拒绝猜测。完整导出在同一个只读快照中分页流式输出；复算校验历史结果与资金守恒，不替代签名验证或重新执行历史规则。

账本写入继续通过 PostgreSQL 跨进程锁保证资金与执行游标顺序。每个服务进程在借出数据库连接前先排队，避免等锁请求占满读连接；登录及设备密钥使用独立原子事务，空闲结算检查不占账本锁。事务内缓存稳定设置，保存点回滚同时恢复缓存；发布执行游标只批量更新消息与版本正文，不重复重建引用索引。批量命令复用已提交的消息状态，并省去一层多余的保存点；任何命令失败仍回滚整批操作。

工作台视图工具栏、画布、列表、排行榜、更正对比和历史面板按需加载。界面模块的等待、失败接入现有绘制完成检查。`npm run test:bundle` 检查实际构建产物：工作台主分包小于 350 KB、所有 JavaScript 分包小于 500 KB，指定可选界面不得进入工作台静态依赖。CI 同时执行该检查。

消息视图只有一个“导出”入口，点击立即打开窗口；未选择旧文件时完整导出，选择已有 JSON 文件则更新导出，仅下载其缺少的执行历史，同时刷新消息、押注、标签及关注状态。文件读取、复算校验、摘要、合并和 JSON 生成在浏览器 Worker 中进行，关闭窗口会终止处理；服务端核对数据来源和完整历史摘要，返回新增记录及最新状态，不接收旧文件正文。合并后重新检查记录连续性与资金守恒，校验通过才允许保存。支持选择保存位置的浏览器可覆盖原文件，其余浏览器下载更新后的完整文件。更新需连接原数据源；缺少执行历史的旧版文件需先完整导出一次。新导出采用紧凑 JSON，去除排版空白，保留全部数据。

生产构建为每次发布生成独立版本标识。已打开页面每分钟检查一次，并在返回页面时立即检查；发现新版本时提示刷新，由用户保存编辑内容后手动确认。入口页面和版本信息不缓存，带内容哈希的资源长期缓存。首次引入此检测功能时，原先打开的旧页面仍需手动刷新一次。

性能复测运行 `npm run test:load`：两个独立 API 进程、8 个测试用户、1/8/24 并发，每档 192 个 HTTP 请求、重复三轮，75% 批量命令写入、25% 增量快照读取；记录吞吐量、读写 P50/P95/P99 和数据库等锁连接数，另验证 32 次相同请求重试、24 次竞争余额及完整账本回放。仅使用 `TEST_DATABASE_URL` 或本地开发数据库，每次创建随机 `gonglun_load_*` schema 并在结束后清理，不读取部署 `DATABASE_URL`。结果写入 `data/performance/`；本次前后对照原始记录保存在 [README/performance](README/performance/)。复测时应独立运行，避免构建、测试或其他负载干扰；本地测量不能当作生产容量承诺。

分类、总结、归并和排列均为消息；主页是查询视图。一次发送的多个操作通过一个事务提交。消息表和消息图都按组织后的当前层级显示；发送时间用于保留既有消息顺序，不能直接作为组织视图的分页边界。分类在父层保持入口，进入后显示内部内容。

工作台先同步完整讨论范围的当前消息及附属状态，由前端 Worker 建立组织、归属、表态和更正模型，完整后才首次显示；不使用不完整的原始消息窗口推测结构。首次准备主动同步，后续后台补齐在页面隐藏时暂停启动下一批。筛选与排行榜继续基于完整讨论范围计算。此方案优先保证显示正确，首次访问仍有完整数据下载成本，尚未实现严格按层级下载正文。

显示范围在组织投影之后确定。浏览器 Worker 按图的组织布局建立加载顺序、计算卡片与框的位置；消息表和普通消息图在接近已显示结构的下边缘时，自动扩展 50 个完整结构单元，无需手动加载。同层关系、可见端点及内联归并、排列成员不会被拆散，所以实际条数可能超过 50。图布局始终使用完整当前范围，按结构计划逐批准备；后续结构的测量不改变此前结构的位置。追加卡片前先显示“正在绘制”窗口，跨过浏览器绘制帧后才挂载卡片；测量、连线与定位完成后恢复操作，失败或等待超过 30 秒时解除等待并提示重试。上一批完成后才允许下一批，范围耗尽立即停止。Worker 不可用时使用相同算法在本地降级计算。

消息图和消息表只渲染可视区域及附近 500 像素的卡片，滚动、缩放和容器尺寸变化每帧最多更新一次。新卡片每批最多额外挂载 32 张用于测量，包含大量成员的单个归并也使用相同限制。离屏卡片卸载后保留测量高度、完整框及滚动范围，关系线保留片段锚点和避让几何；普通往返滚动不重新计算组织布局。屏幕外的关系装饰同时裁剪，关联计数仍来自完整结构。当前选中、文本操作、键盘焦点、仲裁面板及定位目标保留必要卡片；编号、未读及相关消息定位先临时挂载目标，定位完成后恢复可视区域渲染。

闭合分类的成员不会因自动加载而展开。进入分类有独立的显示范围，返回父层恢复已浏览范围；按编号、未读或相关消息定位时显示到目标所在的完整结构。未读判断、筛选与跨范围关联使用完整目录，追溯、记录预览和对比保留各自完整投影规则。服务端负责权限、查询、命令与账本校验，不计算客户端显示布局。

浏览器按 API、账号和讨论范围分别缓存浏览窗口和全局同步进度。全局分页中断后从检查点续传，分页结束后从首批序号补齐期间的变更，再标记完成。刷新复用缓存并只获取增量；数据源重建或游标失效时重新建立缓存。后台只同步当前记录及计算需要的状态，完整执行历史仍通过独立导出接口读取。

新建容器时，每个成员都会生成独立的加入消息，和容器一起原子提交。一次发送按实际消息类型共用一组“真假、价值”输入，同类型每条消息使用相同投入并分别支付协议费，加入消息也单独计费；历史迁移中已豁免的附属记录保持原账。比如正文引用两条消息，在主画布生成 1 条文本、2 条引用，共 3 条；在分类中还会生成正文的 1 条加入，共 4 条，引用本身通过端点显示，不额外生成加入。默认每条真假 1、价值 0，加协议费 1，共 2 点；3 条加入若填写真假 4、价值 0，则真假合计 12、协议费合计 3。追加成员使用同一种加入消息，每次实际移动保留独立记录及原结构的前序依据。当前查看时，一个消息最多只有一条生效的加入记录，位于根层时可以没有。列表中的“移出容器”会将当前查看生效的加入消息选为反对目标，发送后生效。

引用随来源消息显示，更正随目标消息显示；赞同、反对、标注等附属关系也跟随所依赖的消息。它们保留自己的消息编号供引用、讨论和表态，但不能独立加入分类、总结、归并或排列，也不额外生成加入消息。移动依赖消息时，附属关系随之显示。

赞同、反对仅接受目标的真假投入（价值固定为 0）；推荐、冷藏和其他标注仅接受目标的价值投入（真假固定为 0，默认价值 1），本金锁定并参与目标的价值结算。赞同标注按原标注发送，反对标注按互斥项发送，费用预估按转换后的实际类型分组。对表态再表态时，只沿链解析最终目标，本次操作决定赞同或反对方向；直接标注一条表态则评价这条表态自身。这些关系消息不附带自身真假自押，可被推荐或冷藏进行价值押注。

版本 18 `route-relationship-investments-to-targets` 迁移旧关系投入：可确认的未结算本金从关系自身移到正确目标，旧价值费用以追加退款流水转为目标价值本金，不重复扣款。已结算、截止中、修改过或无法核对本金的旧合同保留原财务依据并归档；原消息、轮次和押注保存在 `target_investment_migrations`，旧账本与签名保留。迁移事务失败全部回滚，重启不重复执行。

费用预估与发送动作共用目标归一化和已生效加入记录的判断。新建分类包含其自身、成员加入记录，以及必要的上级加入记录；加入已有分类只计算新增加入。授权结构修改所产生的加入也计入预估。协议费在账户刷新时同步更新，即使余额不变也刷新预计费用。`apps/server/src/publication-costs.test.ts` 使用实际前端发送动作和后端批量提交，逐类比对新增消息数、协议费、价值投入、真假本金、委托报酬和可用余额变化。

归属显示分为个人选择和公共推荐。当前用户创建加入消息或赞同已有加入消息，会立即成为最新个人选择，并保存此前实际生效的个人选择；反对当前选择后沿这条个人前序链恢复。反对未生效的加入不立即改变位置，但会影响后续恢复的候选。没有可用个人赞同选择时，从未被当前用户反对的加入记录中，按所有用户的赞同押注金额选择推荐归属；全部加入记录都被当前用户反对时回到主画布，不用统计推荐恢复已反对的记录。金额相同时按加入先后及消息编号稳定排序。个人选择不被其他人的统计结果覆盖。图、列表、预览与全局筛选使用相同的归属结果，记录区分“当前用户生效”和“推荐生效”，显示状态可能不同于原结构索引。被授权修改而退役的加入记录不会重新参与选择。

赞同或反对保留为独立表态消息，不复制加入内容。比如个人当前选择 D，依次赞同 B、C 后立即显示在 C，反对 C 后恢复 B，再反对 B 后恢复 D；反对未选中的 D 不会移动仍选中的 C。创建新的加入仍保留独立移动记录，A→B→A 中的两次加入 A 可以有不同前序。界面重复追加当前查看已经生效的归属时直接跳过。容器被本人反对时，须先赞同并恢复容器，再赞同加入或新增成员；系统不自动附带容器赞同，也不会因为其他用户的反对而禁止本人的明确选择。失败时整笔事务回滚。

消息上的“加入”标签查看该消息加入容器的全部记录；容器上的“被加入”标签查看成员加入该容器的全部记录。嵌套容器同时具有两种入口，图与列表保持一致；被加入记录从图或列表打开时统一进入分组消息表，上方“当前采用”、下方“未采用”，数量按加入记录计数；目标消息依据当前用户的有效归属分别标为“本容器”“嵌套容器中”“范围外”。旧记录未采用时，消息仍可能是本容器的直接成员；多个目标分别标注，部分目标采用的记录只计一次。分组不使用旧声明推断位置，归属或个人选择变化后同步更新。记录页保留全部历史消息，退出后恢复原视图、筛选、滚动位置和预览。

消息卡片上的“其他相关消息”在独立浮动提示窗中显示，不展开卡片或改变消息布局。窗口按发出、指向本消息分组，保留消息部件选择和“查看”跳转；长列表在窗口内滚动，可点击关闭、按 Esc 或点击外部收起。消息图、消息表和对比视图使用同一入口。

消息表的加入记录入口位于消息 ID 状态标志之后、作者之前。状态标志只描述当前 ID 的消息本身：内部 =／≠ 表示它在个人选择与公共推荐下是否同样显示，绿色圆形实线外框／红色方形虚线外框表示推荐有效／无效。内部相同用灰色，不同用蓝色，不额外叠加左上角差异点；两边都不显示也算相同。正文采用哪条更正、分类成员及归属差异不改变这个 ID 的有效性比较；更正消息由自己的 ID 标志说明，不汇总进被更正消息的状态；右上角蓝实心点表示消息待阅、蓝空心点表示影响或成员待阅，橙色角标表示显示变化。状态与影响窗口默认宽 420px，超过实际可视区域时自动收缩；优先放在入口上下，纵向空间不足且侧边可容纳时放在入口左右，并随滚动、缩放及窗口变化调整。悬停或点击可查看说明，第一行对照阅读记录和显示是否一致，第二行分别说明“选择显示／选择不显示”和“推荐显示／推荐不显示”，并对照两者的显示结果，左侧文字左对齐。提示统一使用“消息待阅”“消息已阅”和“与上次已阅一致／不同”。消息和影响集中在一个区，消息 ID 与已阅、对比按钮在上，影响明细在下，不再显示额外的同时确认提示。赞同、反对按其解析后目标的实际结果判断，加入按当前归属判断。

阅读确认按账户保存为个人状态。原文和文字更正的各显示版本共享原消息的已阅、讨论、表态和资金归属；显示版本仍保留来源，以便重建历史正文和核对引用。消息和影响分别记录，一次已阅只确认当前显示的消息、具体正文版本与本次列出的影响，不代替阅读关系消息自身或分类成员。对比是可选查看入口，窗口底部“已阅”只确认打开时的对比快照，独立于消息和影响的已阅。消息提示与更正装饰入口共享对比状态；确认后对比按钮置灰，仍可再次查看。快照按全部更正候选及各自的有效／无效结果记录；选择、押注或结算导致尚未确认的结果时重新待阅，切回已确认的结果不重复提醒。新增或修改更正仍视为新依据，窗口打开后的变化不计入该次确认。首次消息已阅后，新更正、表态或结算只增加提醒，不重置消息已阅。更正本身是普通消息，自己的阅读、讨论和资金独立，改变原意应发送新的消息。

更正、容器和加入消息产生的影响分别记忆有效与无效结果，确认一种结果不代替确认另一种，切回已确认的结果不因这次切换新增提醒。加入消息是影响来源：当前消息作为目标时，归属变化沿用已有的已阅自动影响；当前消息作为容器时，接收加入只在成员消息区列出，不再额外生成一条自动影响或确认项。消息自身的有效／无效不是来自自己的影响，不放入自身影响列表。加入消息正文、容器正文与成员正文仍独立阅读。作者自动确认只覆盖自己发送时产生的结果，后续由他人造成的结果变化仍需确认。

旧“修改原意”更正在迁移时保留编号转为普通正文，另新建自定义说明为“修正原意”的引用消息。迁移按普通正文与新增引用核算贡献点，费用多扣返还、少扣补扣，允许可用余额为负数；历史合同、签名和原流水保留，差额另记，重复迁移不重复收费。完整规则与实施顺序见[消息更正与正文版本规则](docs/消息更正与正文版本规则.md)。

消息状态与影响窗口汇集此消息各显示版本的影响。赞同、反对、标注、被引用和结算等按类别展示，但每次确认只覆盖已经呈现的具体事件，后续同类事件仍提醒；不把隐藏理由正文算作已阅。加入、主动引用和回复保留具体记录。确认容器不代替确认成员，确认原消息不隐式阅读更正。版本切换和历史预览不改变投票或推荐。旧数据由迁移程序升级，旧合同、历史修订、账本和签名依据保留。完整边界与实施顺序见上面的规则文档。

追溯待阅中的赞同、标注、加入、仲裁和结算等记录随所属消息确认影响，不自动把记录自身的未阅正文及其后续影响继续扩展成任务；已有影响确认不会因此重新待阅，也不暗中确认记录正文。主动把某条记录设为追溯消息或从状态窗口进入该记录时，仍可独立阅读。范围外提醒保留真正未阅的引用、回复来源正文和未阅前文；来源正文已经已阅时，仅在目标消息下确认尚未了解的关系影响。独立正文在范围内被筛选隐藏时，保留临时显示并阅读入口。

阅读与追溯使用同一组当前消息，默认向上 1 层、向下 2 层。进入追溯即阅读整组起点；指定阅读其他消息、阅读最近选中的整组或“已读并继续”切换消息时，自动以新阅读组为起点，沿用当前距离重新计算范围，无需另点“继续追溯”。取消选中仍保留最近一次选择，重复阅读同组不展开分类或重复写入历史。“后退／前进”按实际阅读历史一起恢复消息组、追溯范围及阅读位置，与已阅状态和阅读顺序无关；后退后打开其他消息会清除原来的前进记录。画布内每条当前消息均显示绿色四角及边中短线；各边中间的灰色 ‹、蓝色 ›、橙色 » 分别标注后退、前进和“已读并继续”的目标，按整组标记可见消息。同一消息属于多个目标时，各符号并列显示，前进目标与继续目标可以一致，也可以不同；继续目标的预览与实际跳转复用同一计算。自动切换阅读消息只更新当前追溯，不逐条叠加追溯层；另行进入的追溯来源默认折叠，可返回上一层。阅读区与状态窗口复用每条消息的“消息与影响”明细和确认范围，消息标题均显示类型、ID 及待阅状态，统一显示未阅／已阅分组、影响类别、具体记录及成员入口；每条消息的整块明细可独立折叠，可分别确认，也可明确确认整组。“已读并继续”保存后按所选阅读顺序查找待阅内容。

版本 23 删除历史公开已读／未读消息及其附属操作，按实际账本冲回费用和本金，追加退款流水和删除事件，保留原版本与旧流水供审计及完整导出重放。尚未结算的共用资金池只移除这些消息的投入，其他投入保留；如涉及已经结算的共用资金池或混合操作，预检列出问题，事务整体回滚，避免误退他人资金。迁移同时清理旧的成员批量确认键，重复执行不重复退款。使用 `npm run db:migrate -- --plan` 核对删除数量及退款，再执行 `npm run db:migrate`。

单独查看更正记录只确认该记录及明确呈现的关系影响。确认原消息不以原文、全部更正或对比已阅为前置条件，各显示版本共享消息已阅，具体更正结果仍保存版本依据；后加的候选及影响继续单独提示。赞同、反对、推荐、冷藏发送前仅依据目标阅读状态提供提示，提醒阅读原文与不同更正、辨别是否改变原意；若改变原意，应前往反对该更正。提示不阻止发送，不要求额外勾选；已阅且无新增待阅内容时隐藏。主页筛选分为消息范围（全部、自发、与我相关、关注）和状态（全部、待阅或有新提醒、已阅且无新提醒），不再按显示版本分别计数。

自己发送的消息及其产生的影响自动已阅；自押触发的结算发起消息按实际发起人确认，即使公开署名为系统。自动确认保留明确标为未阅的记录，不代替阅读其他目标正文、他人新增影响或后续系统结算结果。消息已阅且无新影响时，确认按钮置灰，不重复显示已阅状态文字；有新增待确认影响时恢复可点击，点击仅确认当前列出的新增影响。消息与影响共用一个区域，影响分为未阅与已阅两组，数量各在组标题显示一次；未阅默认展开，已阅默认折叠，手动展开、收起的选择随窗口保留。同类影响先按阅读状态分开再汇总，确认后移入已阅组，空分组隐藏。通过消息 ID 跳转，不再显示“跳转未读”按钮，当前容器只显示文字。更正按普通消息行逐条显示，复用已有对比入口，各影响行用浅色下边框线分隔。分类成员按“已阅无新影响”“已阅有新影响”“未阅”分区并显示数量，未阅消息即使已有影响也归入未阅区；已阅无新影响区默认折叠，另外两区默认展开，可手动展开、收起。确认后或出现新影响时自动重新分区，空分区隐藏。

赞同、反对等汇总影响的分类可分别展开、收起，默认折叠；展开后每个消息 ID 单独一行，保留 ID 跳转。未阅、已阅组内按类型固定排序：赞同与反对相邻，推荐、冷藏等标注集中，结算按发起、结果、终止相邻排列；同类型内部保持原顺序。分类的展开选择按未阅、已阅分别保存，随窗口返回恢复。“状态标志说明”也默认折叠。

按关系类型过滤时，分类、总结及其他带正文的关系消息同样参与匹配；选择“更正”可找到被更正的分类和总结，并保留其更正记录。关系消息自身的类型也参与匹配，过滤统计包含这些正文与容器。

影响提示按直接来源、目标及实际正文、归属变化计算，同容器其他成员的回复、结算和正文不会泛化为这条消息的影响。从提示窗跳转查看后返回，恢复窗口的打开状态和滚动位置。归属变化以具体加入消息为来源，接收加入在成员消息区呈现，不重复计算容器消息的成员关系边，也不额外写入容器正文已读记录；没有加入消息的旧归属才以容器消息作为影响来源。不同的历史加入记录分别保留。容器行开头显示类型，当前容器显示为“分类：ID（当前）”或“总结：ID（当前）”，不提供重复跳转。嵌套时，从消息的父容器沿当前有效归属向外追溯，内层排列及外层分类等整条路径上的容器都标为“当前”；容器消息自身、同级其他容器、已移出的旧路径和被否决的嵌套容器不扩展为当前，浏览范围也不会凭空补入无效路径。有效／无效影响按来源消息编号记录，不为接收加入重复生成自动影响。确认清单中的结果不连带确认关系正文、其他消息正文或祖先容器的影响，也不把消息自己列为自己的影响。分类成员仍显示各自的消息与影响进度，并逐条阅读。

版本 24 清理重复的容器归属确认键，以及有明确连带来源且从未单独确认过的容器正文已读记录。新确认记录保存直接／连带来源，单独确认过的证据在之后的覆盖更新中仍保留；旧格式来源不明的正文记录保留，不用同一时间戳推断用户从未单独确认。删除前的原始记录保存至私有 `container_reading_cleanup_archive`，迁移失败全部回滚、重复执行不重复删除，不改变公开消息、贡献点或账本。预检列出待删除、单独确认保留和来源不明保留的数量。

消息图中的归并消息卡使用自身宽度，内部成员或框架加宽不会将消息卡拉满；卡片仍响应宽度更正和编号的实际测量宽度。

消息表将作者、自押、结算入口和投票统计统一放在卡片头部右侧，宽度不足时换行。消息图中的关系消息卡使用较直的圆角、彩色虚线边框与类型色侧边，文本卡保留圆角实线边框；选中和文本选择状态仍使用完整高亮边框。

自押统一显示为 N/M，分别表示当前作者的累计真假投入和价值投入，包括后续追加；协议费和他人的投入不计入。消息图的正文卡在作者下方显示，消息表在作者旁显示，金额随名称一起切换。同一作者对当前正文贡献多条消息时，标签汇总其对应消息的投入，详情仍逐条列示。作者标签随当前阅览正文更新：保留的原文与生效更正分别归属各自发送者，同一人按用户 ID 合并计数，原文及多条更正都出自同一作者时只显示 1 人；改名不改变人数，不同 ID 不因同名合并；缺少 ID 的记录不按名称推断身份。新发送的文本与关系消息保留用户 ID。全部替换的原发送者不计入当前正文作者。多人时显示修正符号和人数，可在标签上滚动切换名称，不使用方向键切换；点击可查看当前正文作者及对应消息的投入，不重复显示正文片段。各消息的首次与追加紧接自押显示在同一行；没有首次记录的旧消息只显示已知累计投入。

消息表和更正记录通过已有的真假、价值统计显示结果，发送操作使用仲裁入口。更正装饰负责打开全部更正记录，消息表中仅显示修正符号与条数，不重复显示“更正”二字。

消息表中的紧凑关系记录使用低对比灰底、细虚线边框和较淡的侧边色条，与普通文本卡区分并降低视觉强调。消息表和消息图共用统计与仲裁入口组件，统一顺序为“真假统计 → 真假仲裁入口 → 价值统计 → 价值仲裁入口”，每项统计紧邻对应入口。真假统计使用 ✓／✕，价值统计使用 ▲／▼，三角符号与数字之间留有间距；统计前不再重复显示仲裁入口的 ⚖️／💎 图标。 每组真假或价值统计分别比较两侧数值，字号保持一致，较大数字加粗并在下方显示短横线；相等时均不突出，符号沿用原样。

点击发送先立即显示进度窗口，跨过浏览器绘制帧后才复制草稿、准备并提交事务；发送开始同时取消旧的延时定位。新增消息直接更新现有画布，避免强制重建画布和浏览器滚动锚定引起定位前的跳动，提交与绘制完成后再按既定顺序定位新消息。

视图工具栏的“返回”和“前进”与浏览器前进、后退共用浏览记录。进入和退出容器、加入记录临时分类、预览等浏览步骤分别保存图或列表模式、清爽及筛选设置、页面和两侧面板的滚动位置；恢复时等待筛选结果与画布布局完成。页面浏览、追溯阅读和正文版本的前进／后退共用最近视图复用机制：消息视图、阅读明细和关系明细各默认保留最近 4 个视图，内部保留 4、8、12、20 个的统一配置和浏览器保存能力，暂不提供界面调整控件。调大不会清空已有视图，调小会淘汰最久未使用的视图并保留当前视图；历史位置仍可重新恢复。缓存保存界面节点、折叠、内部滚动及浮动窗口。离开的视图及其浮窗移出可见页面，暂停布局测量、定位监听和计算任务；恢复时接入当前实时数据，相同布局输入复用计算结果，新增消息、更正或关系变化触发相应更新。切换用户、消息范围或导出文件后清空缓存。返回后重新跳转会清除旧的前进分支。浏览历史仅还原查看状态，不回退消息、表态和已阅记录。
