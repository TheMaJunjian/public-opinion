# 测试

在仓库根目录使用 Node.js 24 或更新版本：

```sh
npm ci
npm run db:up
npm test
npm run test:deployment
npm run build
```

`npm test` 使用 Vitest 运行共享模型、真实 PostgreSQL 后端集成和 React 工作台测试。`npm run db:up` 启动本地 PostgreSQL；每个后端测试使用随机独立 schema，结束后只清理本轮测试创建的 schema。

`access-management.test.ts` 验证邀请制注册、管理员权限与 CSRF、到期与撤销、两个 API 实例争用同一邀请码、注册失败回滚、停用后的全部会话失效及写入拒绝、恢复后重新登录与完整等待时间，以及版本 34 到 35 的无损升级。已有多用户场景通过测试辅助函数生成真实的一次性邀请码，不绕过服务端邀请校验。前端测试覆盖邀请码提交、管理面板生成与撤销、账号停用确认和恢复，以及旧响应不会覆盖已退出或重新登录的会话。

使用其他测试数据库时设置 `TEST_DATABASE_URL`，账号需要创建和删除 schema 的权限。测试不会读取生产用的 `DATABASE_URL`。默认测试地址与本地开发 PostgreSQL 相同，但测试 schema 与应用数据隔离。

开发时可以指定文件或项目缩小范围：

```sh
npx vitest run apps/server/src/ui.test.ts
npx vitest run frontend/src/test/message-workbench-page.test.tsx
npm run typecheck
```

重点检查消息部件及版本引用、事务提交与重复重试、结算守恒和推翻、组织恢复、原发送操作、分页期间的增量同步，以及非线性布局。PostgreSQL 测试还覆盖两个 API 实例并发重试、超额支出、重复结算、嵌套事务回滚、读取快照和跨实例 SSE。浏览器检查使用单独的测试数据库和本地测试账号。

工作台通过只读的 `POST /api/ui/snapshot/query` 请求按需窗口：每页最多 50 条当前层消息，另外补充最多 100 条端点/归属上下文和 50 条附属关系，首屏不追完分页，也不递归展开闭合容器的成员正文。分页、进入分类、关联记录和按编号跳转分别请求对应的游标、范围或 ID。增量请求携带已加载 ID，只返回这些消息的变更和当前视图内有限的新消息，不把全部历史变更正文发送给浏览器；突发新增消息超过一页时保留补拉游标。浏览窗口与全局计算使用独立游标，筛选和排行榜保持整个讨论范围及原有计算规则，完整导出保持独立。

在线首屏需要完整讨论范围的结构索引，以正确计算分类归属、反对与更正链。收到首批浏览窗口后立即启动前端 Worker，与窗口的增量同步并行，使用 `detail=structure` 分页读取结构，每次最多合并四页、共 800 条；旧式完整快照保留原加载路径。索引就绪后，仅补取当前层及其依赖的完整正文。索引已确定依赖集合时，使用 `ids` 与 `includeContext:false` 精确查询，每批最多 200 条、最多三批并发，不再重复扩展端点、父分类和附属关系；普通窗口与编号导航仍保留原上下文查询。分类投影缓存按当前索引和账号隔离，索引更新后重新计算。

正文另有按消息编号复用的内存缓存，初始窗口和跨分类的共同依赖不重复下载。缓存按账号、数据源和结构索引隔离，最多 2,000 条，按完整记录 JSON 的 UTF-16 大小加对象开销估算、上限 32 MiB；超过上限淘汰最久未使用的记录。初始窗口只复用本次登录期间刚收到的网络响应，且数据源、同步序号、消息版本和审核可见性必须一致；仅靠空增量确认的磁盘旧正文不进入这个缓存。缺失批次全部验证成功后才入缓存，失败和取消不留下半批结果；遇到较新序号先追赶索引，版本或权限不一致则重建索引，避免空增量导致一直等待。该缓存不写入 IndexedDB，也不跨账号复用。

完整增量重放后，Worker 附带上次发布序号及期间全部变化 ID，新索引仅继承确认未受影响的正文。变更、删除、统计变化及其引用/更正依赖重新加载，用户详情变化也会淘汰相关记录；投影仍按新结构重算，保证分类归属、成员数和更正结果及时更新。账号或范围切换、审核可见性变化、序号断档、强制重建以及尚未追完增量的命令响应均不继承旧正文。`online-body-cache-updates.test.ts` 覆盖正文版本、引用原文、同版本投注明细、删除、权限与账号边界；`global-catalog.test.ts` 验证跨页变化集合、重建和命令响应不会错误延续增量边界。

服务端结构投影复用本次事务已读取的当前消息计算状态，只解析结构实际需要的引用，跳过片段原文解析、派生描述和投注用户/上下文明细，投注统计直接聚合；完整正文和历史审核记录保留原投影路径。`ui.test.ts` 对结构分页、增量、分类移动、片段更正、结算和完整快照压缩后的结果逐字段比较，`moderation.test.ts` 同时验证受限消息脱敏一致。

快照响应的 `Server-Timing` 提供 `projection`、`moderation`、`db`、`encode` 和启用压缩时的 `gzip` 耗时，单位为毫秒。`db` 是投影及审核内 SQL 执行往返时间之和，包含在前两项内，不能重复相加；不包含路由前的连接池等待、认证中间件或网络传输。浏览器 Network 的请求时间可用于检查其余等待与下载，Performance 中的 `workbench:structure-window`、`workbench:body-load`、`workbench:projection` 和 `workbench:drawing:*` 用于区分结构选取、正文补取、模型投影及各绘图任务完成时间。前端每阶段只保留最新测量，不上传正文、账号或性能日志，取消的任务不记为成功。

全局同步每一页只更新进度，不逐页替换画布。全局筛选和排行榜按需补齐完整正文，复用原有计算规则；后台同步按空闲预算执行，隐藏页面暂停，打开全局功能时优先完成。在线普通列表/消息图按时间顺序首批加载 20 个消息主体及必要依赖，滚动时每次补充 50 个主体的正文，再扩展显示窗口；主体数不等于原始记录数，归属、反对、更正等依赖始终一起加载。当前分类及最近分类保留已展开范围，增量更新不重置为首批；按编号跳转和发送预览会补齐到目标所在位置。旧式完整快照仍按 50 个主体扩展显示窗口；追溯、对比、容器预览、全局筛选和临时记录列表保留完整语义投影。`message-pagination.test.tsx` 检查滚动续页、取消、加载状态变化后仍可重试失败请求；`online-structural-workbench.test.tsx` 检查索引并行启动、精确正文批次、跨分类导航、缓存更新、分页重试与版本失配拒绝。`zhihu-structural-viewer.test.ts` 比较分页与完整加载时的列表/消息图前缀、归属、反对和更正结果。

IndexedDB 按 API 地址、账号与讨论范围分别保存已加载窗口和全局索引。全局记录与分页检查点原子保存；重新进入从未完成分页续传，完成后只补取增量。F5 复用已加载窗口，无变更时不重复下载旧正文；首次访问、缓存不可用或失效时也只加载首屏。服务端核对数据源及同步游标，前端收到失效响应后重建首屏和全局缓存。未完成的下一页不会写入缓存，发送响应的较新序号也不会跳过尚未补齐的其他变更。

`workbench-cache.test.ts` 覆盖页面重建后的增量请求、部分浏览窗口的恢复、显式继续分页、修改与移出、账号及范围隔离、多标签页缓存顺序、分页中断、网络失败重试、缓存失效及存储不可用；`snapshot-client.test.ts` 检查窗口请求与按需分页。`ui.test.ts` 使用真实 PostgreSQL 验证首屏限制、空增量、定向查询以及关闭容器不下载成员正文；页面测试检查“加载更多”、未加载编号的跳转、全局排行榜准备状态、完整统计和显示分页。`global-catalog.test.ts` 与 `global-catalog-cache.test.ts` 覆盖独立全局游标、跨页变更、断点续传、完整缓存复用、存储失败、重建、取消以及命令响应不跳过其他变更。

`format=compact-v1` 将响应中重复的关系记录编码为消息数组索引，前端还原完整记录；额外的独立关系字段仍原样传输。内容审核过滤保留同一响应内共享记录的对象身份，启用审核后也能去除重复关系正文；过滤缓存不跨请求或账号。快照接口按 `Accept-Encoding` 协商 gzip，直接通过 Node 和 SSH 隧道访问时也会压缩。工作台 SSE 使用 `mode=cursor`，通知中只传执行序号；旧客户端的完整事件格式保持兼容。

`snapshot-transport.test.ts`、`snapshot-client.test.ts` 和 `migrate-legacy.test.ts` 覆盖无损还原、旧接口兼容、分页期间的变更、原押注池及旧数据完整性。大样本测试实际迁移 420 条旧文本消息及分类、JOIN 和跨页引用，以每页 100 条遍历所有普通与合并分页，逐字段比较最终消息、JOIN、引用、用户和附属状态，同时检查请求次数及传输字节减少。不同服务器上的实际耗时需要另行测量。
# 生产容器验证

运行 `npm run test:production`，需要 Docker Compose 2.24.4+ 和空闲的本机 54443、54331 端口。脚本使用独立随机 Compose 项目与临时凭据，验证 PostgreSQL、API、Caddy 内部 CA 的 HTTPS、前端静态页面、首位用户保护、Secure Cookie、CSRF、消息写入、API 重启后的持久化、会话及登录；随后运行实际迁移 CLI，将合成旧 Prisma 数据转换到新 schema，重建生产 API 验证 bcrypt 登录、旧消息及余额、新版写入。结束后删除本轮测试容器和卷。内部 CA 测试不替代真实域名的 DNS 与公网证书验收，合成数据不替代真实备份演练。

该验证显式合并仅供本地/CI 的 `docker-compose.build.yml`；生产 Compose 本身只有镜像引用。验证还将已迁移的数据切到镜像只读演练入口，检查错误目标不创建 schema、原 PostgreSQL 容器 ID/启动时间/数据卷不变，以及旧登录、余额、消息和禁止写入的行为。`test:deployment` 另行验证部署脚本在缺库、错误目标、镜像缺失或校验失败时不替换服务，并检查下载校验顺序、无构建更新、配置不改写及显式镜像回退。

`test:deployment` 也通过模拟 Git、Docker 和下载命令运行 `deploy/update.sh`：验证先拉取再调用更新后的部署脚本、脚本自身被拉取覆盖时仍能完成流程，以及本地改动、上游异常、未发布镜像、容器状态异常、运行镜像不符和健康请求失败时的停止行为。这些流程测试不连接生产服务器，也不替代真实容器或公网 HTTPS 验收。

同一命令运行 `scripts/maintenance.test.mjs`，验证交互维护脚本从实际运行目标备份、失败归档保留未完成标记、API 停止时不误用默认库、恢复只创建新库并以单个事务导入、校验文件随备份转移路径、校验失败及已有目标拒绝恢复。恢复选择覆盖嵌套备份与旧单文件备份的序号列表、跳过未完成备份、含空格和中文的文件路径、更换备份目录、手动路径、取消及非法序号。镜像清理覆盖序号多选、去重、待删除清单及一次确认、取消、非法序号、整个批次的保护检查，以及确认后镜像新关联容器时拒绝删除。测试使用模拟 Docker，不连接生产数据库。

`test:deployment` 还运行 `scripts/sync-vps-db.test.mjs`，模拟 SSH/SFTP/Docker 验证 VPS 选择下载、先新建在线备份、只传输所选归档与校验/元数据、一次 SFTP 会话包含全部下载命令且允许密码认证、临时命令文件清理、参数记忆、下载失败保留未完成目录、校验失败不进入恢复、本机 Docker context 与固定项目、已有目标及异常恢复不切换连接、只读检查失败、取消切换、保留配置其他字段，以及 `.env` 并发修改不会被覆盖。本机有 OpenSSH SFTP server 程序时还实际运行批处理，验证三个文件传输和缺文件立即中止；通过 `ssh -G` 检查密码认证选项优先级，不发起网络连接。它不连接真实 VPS，也不改写仓库的 `.env`。

同步脚本测试还验证恢复后先运行独立迁移、再运行数据重放核验，两个子进程均显式连接新本地库；任一步失败都保留旧连接，并使用当前源码的版本清单检查，不依赖旧构建产物。

可显式运行一次真实 PostgreSQL 16 的本地流程检查：

```powershell
node scripts/sync-vps-db.smoke.mjs
```

该检查使用独立随机 Compose 项目、随机本机端口和 tmpfs，创建版本 7 的合成备份，验证 SHA256、schema/行/自增序列恢复、独立升级到当前版本、数据重放核验及配置切换，确认源库仍为版本 7 后移除测试容器。不会连接 SSH/SCP、已有开发库或生产数据库；配置切换只发生在系统临时目录的测试 `.env`。
