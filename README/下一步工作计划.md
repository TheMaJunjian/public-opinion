## 5. 下一步

1. **公开基础版**：发布主题导出 v2，允许参与者下载并离线重建消息和关系状态
2. **真实演示**：按标准演示剧本走完整流程，记录 UI/操作反馈
3. **审计导出**：补充可供第三方复算的 AuditLog、押注、投票、结算轮次和 RuleVersion 数据
4. **经济 replay**：让同一 replay 核心同时支持数据库 AuditLog 和审计导出文件
5. **独立审计节点**：仅在导出与 replay 格式稳定后建设只读验证节点
6. **上链评估**：最后根据验证、成本、隐私、吞吐和治理升级需求决定是否上链

### 文档口径规则

- 当前默认值以 `backend/prisma/seed.ts` 的 RuleVersion v1 为准。
- 当前接口行为以 `backend/src/routes/` 和通过的测试为准。
- 主题导出 `formatVersion=2` 用于公开内容和关系历史；`replayFromExport()` 可离线重建消息、关系 payload、目标和 supersededBy 状态。
- `replay/verify` 仍从数据库 AuditLog 验证经济状态聚合和总量守恒；主题导出不包含完整资金事件，不能替代经济审计导出。
- 旧设计文档可以保留历史决策，但必须明确标注为历史方案或待迁移方案。
