# 云服务器部署（公论 v1 联网测试版）

目标：让外部用户通过公网 URL 体验**真实后端 + 真实 PostgreSQL** 的全部功能。
架构：**一台服务器跑全部**——Caddy 提供 HTTPS 并托管前端静态文件，`/api` 反向代理到 Express 后端，PostgreSQL 独立容器。前端与后端同源，无需 CORS、无需 GitHub Pages。

```text
用户浏览器 ──HTTPS──> Caddy (80/443)
                        ├── /api/* ──> Express API (3000)
                        └── 其他路径 ──> frontend/dist 静态文件
API ──> PostgreSQL (容器内部 5432)
```

---

## 1. 购买建议

| 项目 | 建议 |
|------|------|
| 地域 | **香港或海外**（免 ICP 备案，域名解析后即可用） |
| 配置 | 2C2G 起步，2C4G 更稳（服务器上要跑 `npm run build` + Node + PostgreSQL） |
| 系统 | Ubuntu 22.04 / 24.04 |
| 带宽 | 轻量应用服务器 30M 峰值即可满足小规模测试 |
| 域名 | 另购一个域名（例如 `gonglun.xyz`） |

> 为什么必须用域名：前端使用 WebCrypto 做 Ed25519 签名，浏览器只在 **HTTPS**（或 localhost）下开放该 API。纯 IP + HTTP 会导致签名功能不可用。Caddy 会自动申请免费 HTTPS 证书，前提是域名解析到服务器。

**买中国大陆机房？** 则需要域名 ICP 备案（数周），否则 80/443 无法对外服务。赶时间请选香港。

---

## 2. 域名解析

在域名服务商添加 A 记录，将你准备输入脚本的域名直接解析到服务器公网 IP。例如本次部署使用 `gonglun.xyz`：

```text
类型    主机记录    记录值
A       @         你的服务器公网IP
```

如果使用 `www` 或其他子域名，也需要为该域名添加对应的 A 记录，并在 `deploy/.env.prod` 的 `DOMAIN` 中填写完全相同的域名。当前推荐让同一个域名同时提供网站、API、健康检查和 API 文档。

## 3. 云厂商安全组 / 防火墙

放行入站端口：

```text
22    SSH
80    HTTP
443   HTTPS
```

## 4. 服务器初始化

SSH 登录后执行：

```bash
# 安装 Docker
curl -fsSL https://get.docker.com | sh
sudo systemctl enable --now docker

# 可选：安装 git 以便拉取代码
sudo apt install -y git

# 配置本地防火墙（云安全组放行后再开启 ufw）
sudo ufw allow 22 && sudo ufw allow 80 && sudo ufw allow 443
```

## 5. 获取代码

方式一：git clone（推荐，方便后续更新）

```bash
git clone -b demo-pages-safe 你的仓库地址 public-opinion
```

方式二：本地打包上传（服务器无法访问 GitHub 时）

```powershell
# 本地执行
tar --exclude=node_modules --exclude=dist --exclude=coverage -czf public-opinion.tar.gz backend frontend deploy README package.json
scp public-opinion.tar.gz ubuntu@服务器IP:~/
```

```bash
# 服务器执行
tar -xzf public-opinion.tar.gz
```

## 6. 一键部署

```bash
cd public-opinion
bash deploy/deploy.sh
```

脚本会：

1. 首次运行要求输入域名，自动生成 `deploy/.env.prod`（随机 JWT_SECRET 和数据库密码）
2. 构建前端（`VITE_API_BASE_URL=/api`，前端只使用真实后端，并关闭调试日志）
3. 启动 postgres + api + caddy 三个容器
4. 执行 `prisma migrate deploy` 建表

成功后访问：

```text
https://你的域名/            → 公论站点
https://你的域名/health      → {"status":"ok"}
https://你的域名/api-docs    → Swagger 接口文档

# 本次实际部署
https://gonglun.xyz/          → 公论站点
https://gonglun.xyz/health    → 健康检查
https://gonglun.xyz/api-docs  → Swagger 接口文档
```

> Caddy 首次申请 HTTPS 证书需要约几秒，失败时用 `docker compose -f deploy/docker-compose.prod.yml --env-file deploy/.env.prod logs caddy` 查看原因（通常是域名未解析或 80/443 未放行）。

## 7. 更新代码后重新部署

```bash
cd public-opinion
git pull
bash deploy/deploy.sh
```

脚本幂等：已有 `.env.prod` 时不会重复生成密钥，数据卷保留。

## 8. 数据库备份（必做）

每天定时备份（crontab）：

```bash
crontab -e
# 加入：
0 3 * * * cd /home/ubuntu/public-opinion && docker compose -f deploy/docker-compose.prod.yml --env-file deploy/.env.prod exec -T postgres pg_dump -U gonglun gonglun > /home/ubuntu/backups/gonglun-$(date +\%F).sql
```

```bash
mkdir -p /home/ubuntu/backups
```

建议定期把备份下载到本地（`scp`），防止服务器故障丢数据。

## 9. 上线前检查清单

- [ ] `deploy/.env.prod` 已生成且未提交到 Git
- [ ] `/health` 返回 ok
- [ ] 两个不同浏览器账号能互相看到对方的消息
- [ ] 注册、登录、发消息、关系、押注、结算、审计日志全部走通

- [ ] 数据库备份任务已配置

## 10. 与 GitHub Pages 的关系

- 默认方案（推荐）：不用 GitHub Pages，全部由服务器提供。
- 备用方案：继续用 Pages 托管前端，把仓库 Actions 变量 `VITE_API_BASE_URL` 设为 `https://你的域名/api`。此时服务器仍提供后端 + 数据库；但 Pages 与服务器不是同源，必须确认后端 CORS 配置允许 Pages 域名。
