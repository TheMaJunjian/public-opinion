# 服务器部署

运行时为 Node.js 24，消息和贡献点账本保存在 SQLite。一个 API 进程同时提供前端静态文件，Caddy 提供同源 HTTPS。

服务器需要 Git、Docker Compose 和 OpenSSL，域名指向该服务器，开放 80/443 端口。在仓库中运行：

```sh
bash deploy/deploy.sh
```

脚本更新当前分支，首次询问域名，将域名和随机发起人密钥写入 `deploy/.env.prod`，构建镜像并等待健康检查。部署当前目录而不拉取远程时用 `bash deploy/deploy.sh --no-pull`。

第一位用户注册时需要输入 `.env.prod` 中的 `GONGLUN_FOUNDER_KEY`，以后正常注册无需此密钥。生产浏览器使用 HTTPS，以支持设备签名和安全会话。

```sh
cd deploy
# 查看状态与日志
docker compose -f docker-compose.prod.yml --env-file .env.prod ps
docker compose -f docker-compose.prod.yml --env-file .env.prod logs --tail=100 api
```

`gonglun_data` 命名卷保存 `/app/data/gonglun.sqlite`；更新镜像不会清空数据。备份时先停止 API，再备份整个数据卷，随后启动 API。不要删除该卷，也不要在运行中只复制 SQLite 主文件。

应用健康检查为 `/api/health`。外部只暴露 Caddy 的 80/443；API 3000 端口仅容器网络可访问。`TRUST_PROXY=1` 对应单层 Caddy 代理。

无 Docker 时，在仓库根目录执行 `npm ci && npm run build`，设置 `NODE_ENV=production`、`GONGLUN_FOUNDER_KEY`、`GONGLUN_DB` 后运行 `npm start`，并用同源 HTTPS 代理转发整个站点。
