# 历史标注表态恢复

数据库版本 10：`normalize-historical-annotation-stances`，通过独立迁移程序执行，适用于已经完成版本 9 的数据库。版本 9 处理价值仲裁投票；版本 10 补齐对推荐、冷藏等标注发送的旧赞同／反对关系。

例如，对“原消息上的推荐”发送赞同，迁移后成为同一作者对原消息的另一条推荐。对推荐的反对变为冷藏；其他支持互斥项的标注也沿用当前发送规则。目标版本、部件和文本范围保留。对标注正文的讨论以及原消息正常的真假赞同／反对保持原样。

迁移更新当前消息、历史版本、变更记录、重试缓存、引用索引和个人标记，同时删除转换消息产生的旧赞同／反对显示索引，重新发布相关消息状态，避免标注上继续残留赞同装饰。原始记录和被删除的显示索引备份在私有的 `annotation_stance_message_backups` 中。

消息 ID、作者、时间、修订号和投入保持不变。余额、账本、原轮次、押注、执行记录和签名均校验不变，不重新投票、扣费或结算。重复执行不会重复转换或追加同步事件；失败在同一事务中回滚。

本地于 2026-10-23 预检到 2 条历史标注表态，其中 `9198b104-5b17-44df-84c8-a23857d5864b` 是对推荐 `b6563c66-fa94-4e52-a459-356565c0fe69` 的赞同，转换后推荐原消息 `cmv4klz1h0029md14splwe0vb`。迁移前的本地业务 schema 备份及校验记录位于 `artifacts/annotation-stance-repair/`。

生产发布包含版本 10 的镜像，沿用[历史价值投票恢复说明](历史价值投票消息恢复.md)中的备份、预检、执行与验证步骤。预检和验证新增 `annotationStanceMessages`，完成后 `pending` 和 `unresolved` 均应为 0。正常启动新版 API 也会调用同一独立迁移程序。生产数量以实际预检为准。
