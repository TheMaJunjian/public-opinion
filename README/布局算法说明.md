# 非线性显示

`frontend/src/components/GraphView.tsx` 根据消息、关系和已生效状态生成显示，再由纯布局函数计算位置。

- `stanceLayout.ts` 按执行时解析的目标划分讨论区，赞同、目标、反对分列；保留原关系链供追溯。
- `frameLayout.ts` 从内向外计算组织尺寸，再从外向内放置。嵌套组织只测量和放置一次，循环引用不能造成无限递归。
- `useCardMeasurements.ts` 用稳定的 ResizeObserver 汇集真实卡片尺寸，尺寸不变时不触发布局更新。
- 分类、总结、归并、排列使用同一消息身份；当前被取消的覆盖效果恢复原消息，组织声明及历史仍可查看。
- 卡片默认宽度为 320；用户名显示字符数不超过消息 ID（省略号计入长度），悬停可看全名。表头按实际字体测量所需空间，ID 放不下时自动增宽；卡宽变化只改变列的横向间距，不通过像素反推逻辑列。
- 更正的附加关系依次为“宽度调整、修正文字、修改原意”。宽度调整选择一条当前完整消息，可输入 320–2400 的整数、拖动滑块或卡片右边缘；拖动按画布缩放比例换算，双击手柄恢复默认，发送前仅预览。发送后作为 `CORRECT / WIDTH` 记录保存，按本人立场与公共统计选择有效宽度，独立于正文更正；自动宽度和内部成员所需空间仍是下限。
- 归并、排列及追溯展开的分类、总结从内向外测量。每条引用、支持、反对关系在双方最近的共同容器内计算列：支持位于目标块左侧，引用与反对位于右侧；成员在外部布局中由其所属子框架整体参与避让，连线与统计仍指向原始成员。框内列只由框内关系决定，外部关系不能拉开内部成员；横向排列保留声明顺序。循环列约束压入同一列并纵向避让。
- 部件和固定历史版本的引用不当作当前整条消息。更正提案在授权前只展示提案；已生效的内容从服务器新修订读取。
- 字体、背景和光晕读取推荐投入；押注金额单独展示。

选择文字、来源与目标集合、框选、拖动、缩放、焦点、追溯和对比仍由原工作台入口操作。
