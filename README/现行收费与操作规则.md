# 公论现行收费与操作规则

核对日期：2026-11-08。本文根据当前源码整理，供推广、介绍页、AI 功能说明和实际演示使用。线上规则参数可以调整，具体投入、协议费、审核费、自押、生成消息数量和总消耗以发送前预览为准。

## 贡献点从哪里来

**贡献点是对公论贡献的计量。** 使用、阅读与判断提供讨论生态，举证、纠错与整理产生有价值的信息，开发、设计、推广和运营建设公论，资金与资源支持公论持续运行。贡献的种类、确认方式、计量标准和分配规则，都应公开，并通过公论讨论和完善。

当前实现按以下方式记录和处理，不能只把计时领取当作贡献点的定义：

| 贡献或参与方式 | 当前记录与处理 |
| --- | --- |
| 使用贡献 | 按下述计时规则领取，累计记入“累计使用贡献” |
| 资金贡献 | 按规则确认并实际到账的充值记为“充值贡献” |
| 建设与运营贡献 | 公开记录任务、过程和成果，通过现有提案、认定及授权发放机制处理；开发、设计、推广等尚未全部自动计量 |
| 信息判断与结算 | 为立场投入贡献点，按投票和结算规则重新分配；发送、举证或纠错本身不等于自动获奖 |

“用公论运营公论”是运营原则：一切运营由公论用户负责，所有运营信息在公论上公开。贡献认定和分配也纳入这个过程。这个原则规定共建方式，现有软件的权限和自动执行范围仍按实际功能处理。

### 使用贡献的现行计时规则

- 新账户从 0 点开始。登录后保持公论网页运行，每天第 1 点等待 1 秒，第 2 点等待 2 秒，之后每轮多等 1 秒；到点自动领取并开始下一轮，无需点击、按键或滚动。
- 页面在后台也继续计时，关闭页面后停止自动领取。进度按账号保存，刷新、重新登录或多开页面不会重置或加速。
- 每天北京时间 00:00，上一天尚未领取的那一轮无论是否等满，自动补发 1 点；等待进度和当日递增次数清零，下一轮从 1 秒开始，已有贡献点保留。离线多天只补发离开前正在等待的那一轮。
- 按站内规则确认并实际到账的充值计为“充值贡献”；计时领取和零点补发计为“累计使用贡献”。它们与当前可用余额分别统计，消费不会减少已累计的贡献值。
- 押注结算可能带来收益或损失。站内贡献点分配与现实货币兑换是不同事项，当前操作说明不把兑换、提现或固定回报列为可用功能。

## 每条消息怎样收费

普通用户消息分别设置“真假投入”和“价值投入”，均为非负整数，至少一项大于 0；另外支付协议费。需要审核的内容再分别冻结审核费和自押。审核关系收独立审核押注及协议费；复核收新一轮审核费、追加自押及协议费；审核结算和资金划转收协议费，均不混用真假、价值投入。系统随机派发和收回审核任务、临时阅读权限不收费。

```text
普通消息的消耗 = 真假投入 + 价值投入 + 协议费 + 适用的审核费 + 审核自押
审核消息的消耗 = 审核押注 + 协议费
复核消息的消耗 = 新一轮审核费 + 追加自押 + 协议费
一次操作的总消耗 = 本次所有付费消息的消耗之和 + 需要锁定的委托报酬
```

默认协议费为每条消息 1 点，审核费 6 点、自押 10 点，最低审核押注 2 点。例如，在根层只发送一条真假投入 1 点、价值投入 0 点的文本，默认占用可用点共 18 点，其中发布自押支持通过，参与审核权重和最终盈亏分配。每次复核另需审核费 6 点、自押 10 点及协议费 1 点，共 17 点。若一次操作同时新建文本、回复或引用关系、加入消息等，它们分别计费，不能把一次点击理解为只发送一条消息。

- **真假投入**用于相关消息或部件的赞同、反对押注。
- **价值投入**锁定为价值押注，并创建记录、统计和价值仲裁轮次。普通消息及自动生成的加入消息投入到消息自身；推荐、冷藏等针对目标的价值表态投入到目标消息，与真假押注分别统计。
- **协议费**进入运营资金，不属于押注本金，不随平局退还。
- **组织操作**可能生成独立的加入消息；在分类内发言也可能需要加入消息。预览会合计文本、关系、加入等各类消息的费用。
- **发起结算、请求终止结算**也是付费请求，当前各投入价值 1 点并另付协议费。系统派生的免费记录不额外收取用户消息费用；个人已阅状态不作为公开付费消息发送。
- **余额不足**时不能继续普通付费发送或追加押注。历史数据切换及后续分配调整可能产生负余额，之后获得的点先抵扣欠额。

## 审核、传播与复核

加入记录、没有新增正文的赞同/反对、引用/回复/注释关系、固定原因标注及纯归并/排列免审。“建立关系”等自动说明、内置引用和回复标签不算正文；自定义标题、标签、标注原因和实际新增正文仍需审核。已退役的旧话题容器不生成审核任务。

普通文本、网页、代码、提案、运营公告，以及带正文的总结、分类、委托、正文更正需要审核；自定义标签独立审核，纯结构关系及审核理由免审。结算发起请求、结算记录及结果免审，旧记录中的自动说明不视为待审正文，不冻结审核费或审核自押，也不产生审核任务；历史结算仍在原消息的结算入口查看。内容发布即公开，待审期间可以阅读和传播。审核结算不通过后其他人看到占位卡，引用、摘录等依赖内容一并隐藏，已有记录和资金不删除；结算确认后立即划转资金，不通过的正文仅作者可见。个人投“不通过”后，本人默认看到遮罩，可展开正文并重新遮挡，不改变公开审核结论。复核中仅作者与新一轮随机审核者可见。隐藏的消息不能再用作普通消息的来源或目标，作者也不能绕过。

真假、价值入口左侧显示可点击的通过、不通过统计，点击进入同一审核汇总临时分类；旁边的盾牌按钮打开审核仲裁面板。用户的审核判断和理由依附目标，只在审核临时分类中展示。“纳入审核”、任务分配、结算等系统过程记录不进入讨论画布，也不设独立审核历史入口。消息通知内单独设审核分类，只通知任务接收者、结论相关的作者与参与者、资金受影响的本人；迁移说明不生成通知。发送审核成功后自动进入目标的审核汇总临时分类。临时分类默认同时汇总通过和不通过的理由，按本轮每人最新判断统计，不提供立场筛选。被审核消息始终显示，可切换消息图、消息表；原始记录默认收起，展开或收起只影响审核记录。“运营”的附加关系默认为公告，选择审核后可对一条完整目标消息发送通过、不通过判断，理由可选。审核消息依赖被审核消息，理由保存在关系消息中，仅收审核押注和协议费，不另建正文或收取正文审核费、自押。审核消息在审核临时分类中作为普通文本消息展示，复用普通文本的全部操作、选择和显示逻辑，不另设操作白名单：可作为来源或目标进行回复、支持、反驳、引用、注释、更正、标注、推荐、冷藏、关注、屏蔽、通知、宽度调整，以及分类、总结、归并、排列等。唯一的表态转换是对完整审核判断的赞同、反对形成审核投票；这些后续讨论保留同一被审核版本的归属，重新打开和刷新后仍可查看，不进入普通消息流。更正仅改变理由的显示文字，原审核判断、对象版本和押注记录保持不变；改变立场须新增审核。后续普通讨论仍按普通消息计费与审核。每次重复审核须实际追加押注。理由汇总旁可准备赞同、反对消息，确认押注后发送；对完整审核判断的赞同、反对自动形成同向、反向审核，仍须能阅读对应版本且审核窗口开放；针对理由片段的讨论仍为普通讨论。已登录且能阅读对应版本就能审核，包括作者，无需随机分配；作者可发起自己内容的审核结算，管理员不能授予全局查看权限。

首次启用审核时，生产旧内容初始化为待审核状态，没有历史投票、结算或任务记录；初始审核费和自押按当前规则建立，不补发历史通知。

审核按双方累计押注点数结算，与真假、价值仲裁相同。发布自押、复核自押、历次审核押注均计入对应立场；较大一方胜出，平局为未定（UNKNOWN），退还双方押注本金。不设审核人数门槛，不逐级扩审，复核轮数不影响结果。随机任务默认同时分配 3 人，提供邀请、临时阅读权限和本轮结算资格；有效任务接收者无需先提交判断，也可按已有押注结算，作者也可结算自己的内容。随机任务及临时阅读权限默认 30 分钟有效，超时收回后随机补位，公开正文仍可阅读和审核；本轮已提交审核者在结算前保留阅读与审核权限。累计随机分配上限为 6 人，候选不足或上限耗尽不自动通过。

首次分配和超时补位均只从当前在线的合格用户中随机抽取。登录或前台心跳后 2 分钟内算在线，页面在前台时每 30 秒发送心跳；后台轮询和未过期的登录会话不能维持在线资格。离线只停止接收新任务，已分配任务仍按原 30 分钟期限处理。版本 39 迁移后旧会话等待新心跳，不重复收费。

审核费用于每轮前 3 名不同有效参与者的报酬，每人 2 点，不以判断胜负为条件，重复提交不多领；未使用预算退付款人。奖励名额用尽后，后续参与者仍可通过反方错误押注获得收益。旧内容保留实际冻结预算，例如原预算 3 点只足以支付 1 个 2 点奖励，剩余 1 点返还。

确认审核结算时立即划转资金，不再设置异议等待期或二次划转操作。发布自押计入通过方，复核自押计入申请的相反立场；自押与审核押注共同结算，胜方按投入比例取回本金并分享反方押注。自押计入结算权重，不占随机审核名额、不领取参与报酬。

结算后追加审核须先申请复核。通过或未定内容的登录用户可申请；不通过内容仅作者可申请，未定结论可选择复核自押方向。复核理由必填，每轮重新支付审核费、追加自押并抽取审核者，旧轮次任务和临时阅读权限失效，旧押注保留原立场继续计入结算权重。已发放参与报酬保留，旧轮次未发放报酬在复核开启时结清。前次押注、自押分配撤回并重新锁定，冲正可产生欠额；旧押注仍参与最终资金结算。旧自押保留原立场：申诉不通过押通过，质疑已通过押不通过；与旧审核押注一起参与最终盈亏分配。每次操作的协议费不退。新版有独立审核，历史版本的审核资金仍可在队列中处理。

版本 36 对旧内容按当时标准迁移扣费，余额不足记欠额；迁移幂等，真假、价值资金不混扣。版本 38 切换为随机分级审核，版本 40 改为先公开、否决后隐藏，保留旧预算和账本，均不重复扣费。版本 42 将已有保证金原额转为带立场的自押，不改变余额、账本或已完成结算，缺少可确认的复核历史时回滚。结算和资金划转的协议费可记欠额；新增审核押注、复核费用和自押须有实际可用点，失败操作整体回滚。网页导出只包含当前有权查看的内容，不能用于完整私有历史审计。

## 发言与创建关系

### 发送独立文本

1. 登录后打开消息工作台，不选择关系类型。
2. 输入正文，设置文本的真假、价值投入。
3. 检查发送前的消息数量和总消耗，确认后发送。

### 赞同、反对、推荐或冷藏

1. 选中目标消息或需要表态的部件，所选内容进入候选区（选择暂存区）。
2. 选择赞同、反对，或推荐、冷藏等相应关系，设置投入。
3. 检查目标与预览后发送。单独站队可以不写新正文，也不必选择来源消息；若附带新正文，操作可能同时生成文本和关系消息。

真假立场与价值评价分别处理：赞同、反对用于真假判断；推荐、冷藏用于价值判断。投入按实际指向的消息或部件解释。

### 回复、引用和注释

两种常用方式：

- **写新内容回应已有内容**：选中目标，选择回复、引用或注释，输入正文后发送；预览包含需要新建的文本和关系。
- **连接已有内容**：选中已有消息并加入来源集合，再选中其他消息并加入目标集合，清空候选区，选择关系并发送。

目标集合为空时，候选区可直接作为目标。候选区和目标集合不能同时有内容；同一消息也不能同时作为来源和候选或目标。不同关系对来源、目标、正文有各自要求，发送按钮旁会显示缺失条件。

### 整理与更正

用分类、归并、总结、排列及加入关系组织讨论，可在消息图、列表等视图间切换。回复、更正、支持、反驳和引用等关系可以跨越分类边界，不要求把另一端一并归类。已有总结、归并、排列容器须整体组织，不能抽走其中成员；完整选择全部成员时沿用整体容器选择。更正保留原消息及版本记录；要改变原意时发送新消息。更正、组织和加入仍须按实际生成的消息分别投入、付费。

## 投票、结算与后续翻案

对同一目标、同一版本及同一结算维度的押注：没有进行中轮次，或上一轮已终止并完成结算时，新的押注自动发起新一轮结算；已有进行中轮次时，押注参与当前轮次。终止请求若设有等待时间，截止前的押注仍参与当前轮次。普通消息自身的价值投入与后来针对该消息的推荐、冷藏共用对应的价值轮次。历史上已转入运营资金的价值投入保留原账本，不重复扣款或自动改为押注。

1. 点击消息卡上的“真假仲裁”或“价值仲裁”入口，打开对应面板；没有进行中轮次时可点击“发起结算”，发送前检查请求费用。
2. 在相应维度选择赞同或反对方向，输入正整数点数后投票。投票权重按押注点数计算，而非按人数计算。
3. 点击“结算”并确认，发送终止请求。当前规则若设有等待时间，要到截止后计算；默认等待时间为 0。
4. 对同一结算目标，系统累计相关押注比较双方权重。权重较大方胜出，收回本金并按出资比例分配败方本金；平局退还双方押注本金，单边押注仅返还本金，协议费不退。
5. 后续轮次可以改变结果。系统撤回先前分配、恢复相关本金，再按累计押注重新分配，保留轮次和收支记录；不能把每一轮理解为彼此独立、重复获利。

结算是当前规则和投入形成的阶段性共识，证据、更正和后续讨论仍然有意义。投票获胜不等于客观事实获得永久证明。

## 旧说法与现行口径对照

| 旧说法、操作或常见误解 | 现行说明 |
| --- | --- |
| 普通文本最低 10 点 PRO 自押 | 真假、价值最低合计投入 1 点；另付协议费、审核费并冻结自押，默认合计 18 点 |
| 所有消息都必须附带 PRO 自押 | 可选择真假或价值投入；针对目标的真假、价值表态按各自维度处理 |
| 一次发送固定另收 1 点手续费 | 默认每条付费消息协议费 1 点，参数可调整；复合操作合计全部消息费用 |
| 注册即有赠点或领取旧福利 | 新账户 0 点，按当前计时规则自动获得贡献点 |
| 每次发送都会新建一个轮次 | 对同一结算目标，没有进行中轮次或上一轮已终止并完成结算时，真假或价值押注自动发起新一轮；否则参与当前轮次，分配仍需按规则终止结算 |
| 双击消息即可投票、结算 | 使用消息卡上的真假仲裁、价值仲裁入口 |
| 一点贡献点一票，多数获胜 | 按相应目标、维度的押注点数加权，比较双方累计投入，平局退还本金 |
| 每轮只分配本轮新投入 | 后续结算撤回旧分配，按相关累计押注重新分配 |
