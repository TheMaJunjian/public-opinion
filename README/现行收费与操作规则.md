# 公论现行收费与操作规则

核对日期：2026-11-03。本文根据当前源码整理，供推广、介绍页、AI 功能说明和实际演示使用。线上规则参数可以调整，具体投入、协议费、生成消息数量和总消耗以发送前预览为准。

## 贡献点从哪里来

**贡献点是对公论贡献的计量。** 使用、阅读与判断提供讨论生态，举证、纠错与整理产生有价值的信息，开发、设计、推广和运营建设公论，资金与资源支持公论持续运行。贡献的种类、确认方式、计量标准和分配规则，都应公开，并通过公论讨论和完善。

当前实现按以下方式记录和处理，不能只把计时领取当作贡献点的定义：

| 贡献或参与方式 | 当前记录与处理 |
| --- | --- |
| 使用贡献 | 按下述计时规则领取，累计记入“累计使用贡献” |
| 资金贡献 | 按规则确认并实际到账的充值记为“充值贡献” |
| 建设与运营贡献 | 公开记录任务、过程和成果，通过现有提案、认定及授权发放机制处理；开发、设计、推广等尚未全部自动计量 |
| 信息判断与结算 | 为立场投入贡献点，按投票和结算规则重新分配；发送、举证或纠错本身不等于自动获奖 |

“用公论运营公论”是运营原则：一切运营由公论用户负责，所有运营信息在公论上公开。贡献认定和分配也纳入这个过程。这个原则规定共建方式，现有软件的权限和自动执行范围仍按实际功能处理。

### 使用贡献的现行计时规则

- 新账户从 0 点开始。登录后保持公论网页运行，每天第 1 点等待 1 秒，第 2 点等待 2 秒，之后每轮多等 1 秒；到点自动领取并开始下一轮，无需点击、按键或滚动。
- 页面在后台也继续计时，关闭页面后停止自动领取。进度按账号保存，刷新、重新登录或多开页面不会重置或加速。
- 每天北京时间 00:00，上一天尚未领取的那一轮无论是否等满，自动补发 1 点；等待进度和当日递增次数清零，下一轮从 1 秒开始，已有贡献点保留。离线多天只补发离开前正在等待的那一轮。
- 按站内规则确认并实际到账的充值计为“充值贡献”；计时领取和零点补发计为“累计使用贡献”。它们与当前可用余额分别统计，消费不会减少已累计的贡献值。
- 押注结算可能带来收益或损失。站内贡献点分配与现实货币兑换是不同事项，当前操作说明不把兑换、提现或固定回报列为可用功能。

## 每条消息怎样收费

公开发送的用户消息分别设置“真假投入”和“价值投入”，均为非负整数，至少一项大于 0；另外支付当前规则规定的协议费。真假投入可以为 0，但此时价值投入至少为 1，不能将两项都设为 0。

```text
每条付费消息的消耗 = 真假投入 + 价值投入 + 协议费
一次操作的总消耗 = 本次所有付费消息的消耗之和 + 需要锁定的委托报酬
```

默认协议费为每条消息 1 点。例如，在根层只发送一条真假投入 1 点、价值投入 0 点的文本，默认总消耗为 2 点。若一次操作同时新建文本、回复或引用关系、加入消息等，它们分别计费，不能把一次点击理解为只发送一条消息。

- **真假投入**用于相关消息或部件的赞同、反对押注。
- **价值投入**锁定为价值押注，并创建记录、统计和价值仲裁轮次。普通消息及自动生成的加入消息投入到消息自身；推荐、冷藏等针对目标的价值表态投入到目标消息，与真假押注分别统计。
- **协议费**进入运营资金，不属于押注本金，不随平局退还。
- **组织操作**可能生成独立的加入消息；在分类内发言也可能需要加入消息。预览会合计文本、关系、加入等各类消息的费用。
- **发起结算、请求终止结算**也是付费请求，当前各投入价值 1 点并另付协议费。系统派生的免费记录不额外收取用户消息费用；个人已阅状态不作为公开付费消息发送。
- **余额不足**时不能继续普通付费发送或追加押注。历史数据切换及后续分配调整可能产生负余额，之后获得的点先抵扣欠额。

## 发言与创建关系

### 发送独立文本

1. 登录后打开消息工作台，不选择关系类型。
2. 输入正文，设置文本的真假、价值投入。
3. 检查发送前的消息数量和总消耗，确认后发送。

### 赞同、反对、推荐或冷藏

1. 选中目标消息或需要表态的部件，所选内容进入候选区（选择暂存区）。
2. 选择赞同、反对，或推荐、冷藏等相应关系，设置投入。
3. 检查目标与预览后发送。单独站队可以不写新正文，也不必选择来源消息；若附带新正文，操作可能同时生成文本和关系消息。

真假立场与价值评价分别处理：赞同、反对用于真假判断；推荐、冷藏用于价值判断。投入按实际指向的消息或部件解释。

### 回复、引用和注释

两种常用方式：

- **写新内容回应已有内容**：选中目标，选择回复、引用或注释，输入正文后发送；预览包含需要新建的文本和关系。
- **连接已有内容**：选中已有消息并加入来源集合，再选中其他消息并加入目标集合，清空候选区，选择关系并发送。

目标集合为空时，候选区可直接作为目标。候选区和目标集合不能同时有内容；同一消息也不能同时作为来源和候选或目标。不同关系对来源、目标、正文有各自要求，发送按钮旁会显示缺失条件。

### 整理与更正

用分类、归并、总结、排列及加入关系组织讨论，可在消息图、列表等视图间切换。更正保留原消息及版本记录；要改变原意时发送新消息。更正、组织和加入仍须按实际生成的消息分别投入、付费。

## 投票、结算与后续翻案

对同一目标、同一版本及同一结算维度的押注：没有进行中轮次，或上一轮已终止并完成结算时，新的押注自动发起新一轮结算；已有进行中轮次时，押注参与当前轮次。终止请求若设有等待时间，截止前的押注仍参与当前轮次。普通消息自身的价值投入与后来针对该消息的推荐、冷藏共用对应的价值轮次。历史上已转入运营资金的价值投入保留原账本，不重复扣款或自动改为押注。

1. 点击消息卡上的“真假仲裁”或“价值仲裁”入口，打开对应面板；没有进行中轮次时可点击“发起结算”，发送前检查请求费用。
2. 在相应维度选择赞同或反对方向，输入正整数点数后投票。投票权重按押注点数计算，而非按人数计算。
3. 点击“结算”并确认，发送终止请求。当前规则若设有等待时间，要到截止后计算；默认等待时间为 0。
4. 对同一结算目标，系统累计相关押注比较双方权重。权重较大方胜出，收回本金并按出资比例分配败方本金；平局退还双方押注本金，单边押注仅返还本金，协议费不退。
5. 后续轮次可以改变结果。系统撤回先前分配、恢复相关本金，再按累计押注重新分配，保留轮次和收支记录；不能把每一轮理解为彼此独立、重复获利。

结算是当前规则和投入形成的阶段性共识，证据、更正和后续讨论仍然有意义。投票获胜不等于客观事实获得永久证明。

## 旧说法与现行口径对照

| 旧说法、操作或常见误解 | 现行说明 |
| --- | --- |
| 普通文本最低 10 点 PRO 自押 | 真假、价值至少一项大于 0；最低合计投入 1 点，另付协议费 |
| 所有消息都必须附带 PRO 自押 | 可选择真假或价值投入；针对目标的真假、价值表态按各自维度处理 |
| 一次发送固定另收 1 点手续费 | 默认每条付费消息协议费 1 点，参数可调整；复合操作合计全部消息费用 |
| 注册即有赠点或领取旧福利 | 新账户 0 点，按当前计时规则自动获得贡献点 |
| 每次发送都会新建一个轮次 | 对同一结算目标，没有进行中轮次或上一轮已终止并完成结算时，真假或价值押注自动发起新一轮；否则参与当前轮次，分配仍需按规则终止结算 |
| 双击消息即可投票、结算 | 使用消息卡上的真假仲裁、价值仲裁入口 |
| 一点贡献点一票，多数获胜 | 按相应目标、维度的押注点数加权，比较双方累计投入，平局退还本金 |
| 每轮只分配本轮新投入 | 后续结算撤回旧分配，按相关累计押注重新分配 |
| 打开 `/topics` 或旧议题页开始 | 线上使用 `/#/messages`；开发环境使用 `/messages`。旧话题地址已停用 |
| 单独进入 `backend` 目录启动 | 仓库根目录运行 `npm run dev`，见根目录 README 的环境要求 |
| 贡献点可自由兑换或保证获得回报 | 当前说明只涵盖已有贡献点收支与结算；兑换及更大收益分配设想见规划资料 |
