# 给楚门设计的工具

更新：2026-11-03。

## 一、初衷：让公开的信息真正用起来

楚门需要公开透明，也需要一套能把信息记录、讨论、判断和使用起来的工具。公开之后，谁来识别信息、谁来判断价值、谁来确认贡献、谁来决定分配？

这个工具的名字，叫公论。它让成员共同参与一场永恒、递归、迭代、追溯、求是的会议。

## 二、工具定位：争论、辩论、线上文字开会

**公论是争论、辩论和线上文字开会的工具：讨论、投票、结算，让争论有结果。**

公论中有：发言投票（权），胜利的一方获得贡献点（钱），给所有人留下被认可的信息（真理）。

提出一个问题，摆出证据，公开站队，为自己的判断投票，再通过结算形成结果。新的证据可以继续推动修正与翻案，后来的人可以接着讨论，不必每次都从头开始。

胜负、押注和结算让参与具有博弈机制；公论的主要用途，是处理真实的争论、决策和协作。

## 三、信息结构：消息，消息的关系，关系也是消息

当多个问题挤在同一条消息流里，发言容易互相覆盖，证据与观点的联系也容易丢失。公论用非线性的消息图，把这些联系直接记录和显示出来。

- 多个问题并行讨论，观点和证据保留各自的脉络。
- 回复、引用和注释可以连接消息，也可以指向具体部件或片段。
- 关系本身也是消息，可以被回复、引用、赞同、反对和更正。
- 分类、归并、总结、排列和加入关系帮助组织信息。
- 更正、正文版本、已阅和相关影响保留来龙去脉，帮助继续阅读。

最重要的是，真正实现**在聊天里开会**：观点有依据，立场有记录，结论能继续被检验。

## 四、贡献点：对公论贡献的计量

信息的判断和整理需要人做，工具的开发和运营也需要人做。这些贡献都值得记录，也要有认定与分配的方法。

**贡献点是对公论贡献的计量。** 使用与关注、提供证据、识别错误、整理讨论、开发设计、推广运营，以及资金和资源支持，都是公论需要的贡献。

贡献怎么确认、计量多少、如何发放和分配，都在公论里公开讨论和完善。当前计时领取记录使用贡献，确认到账的充值记录资金贡献；建设和运营贡献通过公开事项、认定及授权发放处理，逐类自动计量仍在完善。具体来源与收费见[现行收费与操作规则](./现行收费与操作规则.md)。

## 五、判断与结算：让立场有分量

参与者可以对消息和相关部件表达赞同、反对，也可以推荐或冷藏信息。真假与价值分别投入、分别处理，让大家既能讨论“对不对”，也能讨论“有没有价值”。

押注按贡献点数计算权重。结算时，胜方收回本金并按比例分配败方本金，平局退还押注本金；后续结算可撤回旧分配，再按相关累计押注重新分配。讨论、轮次和调整记录都保留下来。

这让判断与结果产生联系：认真举证和纠错的人有动力，站错队也有需要承担的成本。

## 六、用公论运营公论

招合伙人，条件不限。\
线上运营，信息公开。\
投票结算，按功分配。\
——欢迎加入楚门计划。

**一切运营由公论用户负责，所有运营信息在公论上公开。** 这是公论的运营原则。

做什么功能、怎样推广、谁来承接工作、资源怎么使用、贡献怎样认定、收入如何分配，都在公论里提出、承接、记录、讨论和结算。创始人、专业团队、合伙人和普通用户都参与其中，也都留下决定、执行与贡献的记录。

```text
提出事项 → 公开承接 → 记录过程与成果 → 讨论与举证
  → 投票结算 → 按功分配 → 继续复查
```

软件已有消息、提案、结算、收支和授权发放等能力；各类运营过程的自动化与权限开放按实际建设逐步推进。把公论建设起来、运营起来，就是公论的第一个真实协作场景。

## 七、公开透明是原则，技术路线继续比较

此前考虑通过去中心化来实现公开监督。现在正在重新比较其成本与收益，也考虑“透明中心”：保留集中运行和明确的执行责任，把运营信息、决定、执行与分配公开，让中心本身接受用户监督。

当前系统中心化运行。透明中心、独立复核与去中心化方案都可以按成本、效率和可核验程度继续比较；独立节点与上链按实际需要选择，路线尚未定案。

核心始终是：**一切记录在案，是非自有公论。**
