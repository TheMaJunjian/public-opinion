# 开发环境

需要 Node.js 24 或更新版本，以及已启动的 Docker。首次运行时将 `.env.example` 复制为 `.env`；已有 `.env` 则保留并配置其中的 `DATABASE_URL`。在仓库根目录执行：

```powershell
npm ci
npm run dev
```

脚本先启动 PostgreSQL 16 并等待健康检查，再启动 API 和前端。浏览器访问 http://localhost:5173；API 监听 http://127.0.0.1:3000。数据库地址为 `postgresql://gonglun:gonglun_dev@127.0.0.1:54329/gonglun`，只向本机开放，数据保存在 Docker 卷 `gonglun-dev_postgres_data` 中。首次连接会自动建表，开发环境可以直接注册，首位用户成为发起人。

`Ctrl+C` 结束 API 和前端服务，数据库继续运行；下次执行同一命令即可继续使用数据。也可以运行 `deploy/start.ps1`。单独启动或停止本地数据库：

```powershell
node scripts/postgres.mjs
docker compose -f deploy/docker-compose.dev.yml stop postgres
```

已有 PostgreSQL 时，将连接地址写入根目录 `.env` 的 `DATABASE_URL`，或在 PowerShell 设置 `$env:DATABASE_URL`。开发脚本会连接指定的数据库，不再启动默认数据库容器。数据库需要提前创建，账号需要在该数据库内建表的权限；示例变量见 `.env.example`。

## 从 VPS 备份更新本地数据

先在运行本地网站的终端按 `Ctrl+C`，然后在电脑的 PowerShell、仓库根目录运行：

```powershell
.\deploy\sync-vps-db.ps1
```

如果 Windows 阻止运行未签名的本地脚本，可以只为当前 PowerShell 会话设置，然后仍在同一窗口运行脚本：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\deploy\sync-vps-db.ps1
```

需要已安装项目依赖的 Node.js 24、已启动的 Docker Desktop，以及 Windows OpenSSH 客户端（`ssh`、`sftp`）。也可运行 `node scripts/sync-vps-db.mjs`，但此入口不能清除父 PowerShell 中已有的连接环境变量；切换后须自行清除 `Env:DATABASE_URL`、`Env:DATABASE_SCHEMA`。

菜单提供三个入口：从 VPS 按序号选择已有备份并下载恢复；按序号选择已下载到电脑的备份；先在 VPS 新建在线备份，再选择下载恢复。生产数据一直更新时选第三项：脚本通过 SSH 调用现有 `deploy/manage.sh backup`，在远程终端确认实际生产数据库和输出目录；完成后返回本地，选择刚生成的备份。选择已有备份只导入该快照时刻的数据，不会自动包含后续生产写入。

首次按提示输入 VPS 地址、SSH 端口、用户名、远程部署目录及备份目录；SSH 密码或密钥口令由 OpenSSH 自行提示。连接参数和本地下载目录保存在被 Git 忽略的 `.env.vps-sync.json`，下次回车沿用；不保存密码或私钥。远程目录使用绝对路径，支持字母、数字、下划线、点、斜线和短横线。远程备份目录默认是部署目录下的 `backups`；如新建备份时使用其他输出目录，本地查询时也须指定同一目录。

默认本地目录为 `deploy/backups`。脚本列出备份序号，选择一个即可；回车或 `0` 取消。远程查询跳过未完成的 `.partial.` 目录；下载只复制所选 `.dump` 和同目录的校验/元数据文件，不复制服务器的 `.env.prod` 或其他部署配置。这些文件在同一个 SFTP 会话中依次下载，下载阶段认证一次即可，不会每个文件都重新输入密码；生成远程备份和查询列表仍是独立 SSH 连接，可能另行提示认证。密码输错时 OpenSSH 仍会提示重试。每次下载使用独立临时目录，任一文件传输失败就中止，临时 SFTP 命令文件随会话结束删除，SHA256 校验通过才标记完成；下载或校验失败保留 `.partial.` 文件夹，不覆盖以前成功的备份。本地列表也跳过未完成目录。恢复要求 `.dump.sha256` 或 `SHA256SUMS` 校验文件存在；优先使用备份 `metadata.txt` 中的 schema，仍由你确认。

之后输入一个新的本地库名，脚本使用固定的本地开发 Compose 项目 `gonglun-dev` 和 `127.0.0.1:54329` 恢复，不沿用 `.env` 中可能指向服务器的连接。它检查 Docker context 为本机套接字，并显式指定 context 和项目名。已有目标库直接拒绝；从 `template0` 创建新库，用 `pg_restore --no-owner --no-acl --exit-on-error --single-transaction` 导入后，只读检查业务 schema、已有用户和数据库模式。空库、旧 Prisma 库、只读演练库等不适合作为当前本地网站数据的目标会停止切换，需先按相应迁移/演练流程处理。

恢复和检查成功后显示当前连接、目标连接及用户数，输入一次 `y` 才切换根目录 `.env`。原配置保存在被 Git 忽略的 `.env.before-vps-sync-时间戳-随机后缀`，只更新 `DATABASE_URL`、`DATABASE_SCHEMA`，其他配置保留；操作期间 `.env` 被其他程序修改时停止切换，避免覆盖。任何下载、校验、创建、恢复或检查失败都不会改写原连接。旧本地数据库保留，新建失败库也保留供检查；脚本不删除数据库、卷或停止生产服务。

PowerShell 入口在成功切换后清除当前终端中覆盖 `.env` 的 `DATABASE_URL`、`DATABASE_SCHEMA`。重新运行 `npm run dev`，打开 http://localhost:5173 验证登录、消息和余额。脚本不会自动启动或重启网站。自动化测试的 `TEST_DATABASE_URL` 保持原设置，不会因本地网站切换而改为生产快照库。

生产构建在同一个数据库上运行：

```powershell
npm run build
npm start
```

构建后的页面和 API 均由 3000 端口提供。`npm start` 需要数据库已运行；服务器部署和数据库备份见 [服务器部署](云服务器部署.md)。
