# 重启后启动开发环境

本文档说明如何在 Windows / VS Code 中启动「公论」开发环境，并区分两种模式：

- 本地开发模式：Docker 只启动 PostgreSQL，后端和前端都用 `npm run dev` 启动。推荐日常开发使用。
- Docker 部署模式：Docker 同时启动 PostgreSQL 和后端 API。用于接近部署环境的验证。

---

## 前提条件

- Docker Desktop 已安装并处于 Engine running 状态。
- Node.js 20+ 已安装。
- 前后端依赖已安装；如果没有安装过，分别在 `backend/` 和 `frontend/` 执行 `npm install`。
- 后端环境变量文件已准备好。开发环境可从示例复制：

```powershell
cd d:\Projects\public-opinion\backend
copy .env.example .env
```

默认 `.env.example` 使用本地 PostgreSQL 地址：

```text
DATABASE_URL="postgresql://gonglun:gonglun_password@localhost:5432/gonglun"
JWT_SECRET="your-secret-key-change-in-production"
PORT=3000
```

---

## 模式一：本地开发模式（推荐）

这个模式下只用 Docker 跑数据库，后端热重载和前端 Vite 都在本机运行。

### 1. 启动 PostgreSQL

```powershell
cd d:\Projects\public-opinion\backend
docker-compose up -d postgres
```

确认数据库容器已启动：

```powershell
docker-compose ps
```

看到 `postgres` 状态为 `Up` 即可。

### 2. 应用数据库迁移

首次启动、迁移文件变化后，执行：

```powershell
cd d:\Projects\public-opinion\backend
npm run db:migrate
```

如果只是普通重启，数据库卷没有删除，通常不需要重复迁移。

### 3. 启动后端开发服务器

```powershell
cd d:\Projects\public-opinion\backend
npm run dev
```

后端默认地址：

```text
http://localhost:3000
```

Swagger 文档：

```text
http://localhost:3000/api-docs
```

### 4. 启动前端开发服务器

新开一个终端：

```powershell
cd d:\Projects\public-opinion\frontend
npm run dev
```

前端默认地址：

```text
http://localhost:5173
```

Vite 会把 `/api` 请求代理到 `http://localhost:3000`。

## 模式二：Docker 部署模式

这个模式下 Docker 同时启动数据库和后端 API。

```powershell
cd d:\Projects\public-opinion\backend
docker-compose up -d
```

如果后端容器是首次启动，或迁移文件变化后，执行：

```powershell
docker-compose exec api npx prisma migrate deploy
```

这种模式适合验证容器化后端。前端仍可本地启动：

```powershell
cd d:\Projects\public-opinion\frontend
npm run dev
```

如果要切回本地开发模式，先停止 Docker 里的 API，避免 3000 端口冲突：

```powershell
cd d:\Projects\public-opinion\backend
docker-compose stop api
```

## 常见问题

### Docker Desktop 卡在 Starting the Docker Engine

通常是 WSL2 没响应。按顺序执行：

```powershell
wsl --shutdown
taskkill /F /IM "Docker Desktop.exe"
taskkill /F /IM "com.docker.backend.exe"
```

然后重新打开 Docker Desktop。仍不行时可以尝试：

```powershell
wsl --update
```

### `docker` 或 `docker-compose` command not found

先启动 Docker Desktop，并确认 Docker CLI 已加入 PATH。新开一个 PowerShell 后再运行：

```powershell
docker --version
docker-compose --version
```

### 后端数据库连接失败

确认 PostgreSQL 容器正在运行：

```powershell
cd d:\Projects\public-opinion\backend
docker-compose ps
```

如果没有运行：

```powershell
docker-compose up -d postgres
```

也要确认 `backend/.env` 中的 `DATABASE_URL` 指向本地数据库：

```text
postgresql://gonglun:gonglun_password@localhost:5432/gonglun
```

### 3000 端口被占用

先检查占用：

```powershell
netstat -ano | findstr :3000
```

如果是 Docker API 容器占用，而你要用本地 `npm run dev`：

```powershell
cd d:\Projects\public-opinion\backend
docker-compose stop api
```

如果是其他进程占用，可按 PID 结束：

```powershell
taskkill /PID <PID> /F
```

### 5173 端口被占用

Vite 通常会自动换端口。也可以手动检查：

```powershell
netstat -ano | findstr :5173
```

### 前端页面空白或 API 请求失败

按顺序确认：

1. 后端 `npm run dev` 已启动且监听 `http://localhost:3000`。
2. 前端 `npm run dev` 输出的 Local 地址已打开。
3. 浏览器控制台没有登录 token 或接口 401/500 等错误。
4. Vite 代理仍指向 `http://localhost:3000`，配置位于 `frontend/vite.config.ts`。
