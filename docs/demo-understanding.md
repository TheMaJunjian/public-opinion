### 2.2 候选区流转

```
  [消息/片段/关系]
       │ 单击选中
       ▼
  [候选区 Draft]
       │
  ┌────┴────┐
  ▼         ▼
[来源集合] [目标集合]
```

| Targets（目标集合）| `message` / `text-fragment` / `relation` | 无类型限制 |

## 3. 非线性结构视图渲染规则

### 3.1 列布局算法

```
源消息（source）位于左侧（较小列号）
目标消息（target）位于右侧（较大列号）

约束传播：
  对每条 edge-label / edge-decoration 关系：
    col(target) >= col(source) + 1

初始：所有消息 col = 0
迭代直到稳定（最多 MAX_LAYOUT_ITERATIONS=200 次）

位置计算：
  x = PAD + col * (CARD_W + COL_GAP)
  y = PAD + row * (CARD_H + ROW_GAP)
  
  CARD_W = 220, CARD_H = 110
  COL_GAP = 80,  ROW_GAP = 28, PAD = 40
```

### 3.2 边渲染（Bezier 曲线）

- **类型**：三次贝塞尔曲线（cubic bezier）  
- **锚点方向**：源消息（左侧）右中心边界 → 目标消息（右侧）左中心边界  
- **路径公式**：
  ```
  x1 = source.x + CARD_W       // source 右边界
  y1 = source.y + CARD_H / 2   // source 中心高
  x2 = target.x                 // target 左边界
  y2 = target.y + CARD_H / 2   // target 中心高
  
  dx = |x2 - x1|
  cpx1 = x1 + dx * 0.45
  cpy1 = y1
  cpx2 = x2 - dx * 0.45
  cpy2 = y2
  
  path = "M x1 y1 C cpx1 cpy1 cpx2 cpy2 x2 y2"
  ```
- **箭头**：SVG `<marker>` 指向 x2,y2（目标左边界），即箭头指向目标  
- **颜色**：每种关系类型有独立颜色（见 `PRESENTATION_SPECS`）

### 3.3 边标签文本避让策略

- 标签定位在贝塞尔中点（t=0.5）  
- 宽度 100px，居中对齐  
- z-index: 10（高于卡片 z-index: 5）  
- 多条边时：标签位置在中点 Y 方向加小偏移（`edgeIndex * 2px`），防止重叠  
- 标签不能覆盖消息正文：通过将边从右边界出发、SVG 层在卡片后面，配合足够 z-index 分层实现

### 3.4 z-index 层级

| 元素 | z-index |
|------|---------|
| SVG 边层 | 0 |
| 消息卡片（普通）| 5 |
| 消息卡片（文本选择模式）| 15 |
| 边标签按钮 | 10 |
| 装饰 badge | 卡片内，z-index 继承 |

### 3.5 Pass 1 / Pass 2 两遍渲染

- **Pass 1**：源消息 → 文本消息（`ref.kind === 'message' | 'text-fragment'`），记录每条边的标签位置  
- **Pass 2**：源消息 → 关系消息（`ref.kind === 'relation'`），箭头指向 Pass 1 记录的标签位置（不指向来源卡片）

## 4. 焦点模式语义

### 4.1 进入焦点模式

1. 用户点击右侧 "开启" 按钮 → `focusMode = true`  
2. 选择焦点消息 → `focusMessageId = <msgId>`  
3. 视图筛选为焦点消息 ± N 跳以内的消息和关系  

### 4.2 跳数（hop）定义

```
hop = 文本消息之间经过的关系链数
（每经过一条关系边 = 1 跳）
```

### 4.3 退出焦点

- **退出焦点（exit focus）**：清除 `focusMessageId`，保留 `focusMode=true`（视图回到全量但模式仍开启）  
- **退出全部（exit all）**：同时清除 `focusMode=false` 和 `focusMessageId=''`  

### 4.4 视图过滤规则

```typescript
buildFocusSubgraph(messages, relations, focusMessageId, focusHops)
  → { visibleMessages: Set<string>, visibleRelations: Set<string> }
```

- 从 `focusMessageId` 出发，BFS 遍历关系图，N 跳可达的文本消息加入集合  
- 涉及集合内消息的关系全部包含

## 5. 四类发送/建关系流程（A/B/C/D）

| 操作 | 触发条件 | 语义 |
|------|---------|------|
| **A** 仅发送消息 | 输入框有内容 | 创建新文本消息，不建立关系 |
| **B** 发送并建立关系（候选作目标）| 输入框有内容 + 候选区非空 | 新消息 = 来源；候选区 = 目标；用当前选中关系类型建立关系 |
| **C** 发送并建立关系（Targets集合）| 输入框有内容 + 目标集合非空 | 新消息 = 来源；Targets集合 = 目标；建立关系 |
| **D** 仅用已有消息建立关系 | 来源集合非空 + 目标集合非空 | Sources集合第一项 = 来源消息；Targets集合 = 目标；不发新消息 |

## 7. 新增关系类型扩展设计

### 7.1 前端展现规格扩展

在 `frontend/src/types/index.ts` 中的 `PRESENTATION_SPECS` 对象内新增一条记录即可：

```typescript
// 示例：添加"质疑"关系类型
QUESTION: { kind: 'edge-label', label: '质疑', color: 'orange', formsTrees: false },
```

同时在 `RelationType` 联合类型中追加类型字符串：
```typescript
| 'QUESTION'  // 质疑
```

### 7.2 后端数据模型/校验扩展点

后端使用集中化的关系类型模块（`backend/src/lib/relationTypes.ts`）：

```typescript
// 只需在此数组末尾追加
export const RELATION_TYPES = [
  ...existing...,
  'QUESTION',  // 质疑
] as const;
```

- DB 列 `relationType` 为 `TEXT` 类型，无需迁移
- Zod schema 会自动包含新类型（因为 schema 引用同一数组）
- 前端 `PRESENTATION_SPECS` 需同步更新以提供渲染规则

### 7.3 TargetRef 扩展点

如需新增 target 类型（如 "topic fragment"），需要：
1. 在 `frontend/src/types/index.ts` 的 `TargetRef` 联合类型追加新的 discriminated union
2. 在 `backend/src/lib/targetRefSchema.ts`（建议提取）中追加对应 zod schema
