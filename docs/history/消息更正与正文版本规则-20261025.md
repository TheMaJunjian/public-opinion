# 消息更正、正文版本、已阅与影响归属规则

整理日期：2026-10-25。

本文是本轮讨论形成的统一规则与实现对照。第 1—9 节规定行为，第 10 节保留实施前的问题基线，第 11—12 节说明调整顺序和验收要求，第 13 节记录本次实现及迁移边界。代码调整不代表已经部署或已对实际数据库执行迁移。

## 1. 对象与版本身份

| 对象 | 定义 | 是否随查看选择变化 |
|---|---|---|
| 消息 M | 一条消息的持续身份 | 否 |
| 存储版本 M.r | 原消息实际保存的部件及内容；授权修改可以产生 r+1 | 历史版本不变 |
| 更正 C.c | 针对明确的 M.r、部件或片段提出的修改；c 是更正消息自己的存储版本 | 历史记录不变 |
| 正文版本 V | 对同一 M.r 采用一组兼容更正得到的完整正文，原文采用空集合 | 否 |
| 原意语境 S | M.r 加上该正文采用的全部“修改原意”更正，用于区分正文含义的评价 | 否 |
| 显示方案 | 按个人选择、公共推荐及组织关系计算出的默认显示结果 | 是 |
| 阅览选择 | 跟随默认、推荐或个人方案，或者固定查看某个正文版本 | 是 |

正文版本键由“消息编号、基础存储版本、去重排序后的更正编号及更正存储版本”构成。原意语境键使用相同的消息与基础版本，但只包含其中的 MEANING 更正。另保存正文摘要用于校验，不能用摘要代替来源身份。

规则如下：

1. 更正集合的排列顺序不产生新版本；同一组更正必须得到同一版本键与正文。
2. 正文文字相同但更正来源不同，仍是两个版本；界面可以提示“正文相同、来源不同”，必须能分别查看其来源、影响和已阅。只有来源完全相同的“个人／推荐”入口可以合并。
3. `current`、`personal`、`recommended` 是会重新解析的选择入口，不是版本编号。已阅、引用、表态和资金执行不能只保存这些入口名。
4. 固定预览 V 不改变用户对更正的立场，也不改变个人默认方案。跟随方案会重新解析正文；固定预览保留 V，并提示它与默认方案的差异。
5. 新的正文更正仍针对原消息的明确存储版本，不以某条更正消息为新正文基底。不冲突的更正可以组合，不能因此把更正链当成连续存储修订。
6. 在更正后的文字上选取片段发送操作时，必须保存所见正文版本及该版本内的片段地址；若要创建新的更正，还须正确映射到基础版本地址。无法确定映射时要求重新选择，不能把显示坐标直接写成原文坐标。
7. 授权修改产生 M.r+1 后，旧更正继续属于 M.r，不自动套到 M.r+1。旧引用、已阅、表态和合同按原依据保留。
8. 不要求枚举所有更正组合。保留可重建的版本身份，并提供原文、实际选择、推荐、候选单独效果及已查看或被引用的历史组合入口。

## 2. 更正类型及其作用

| 类型 | 协议含义 | 正文版本 | 原意语境 | 对历史正文评价的处理 |
|---|---|---|---|---|
| TEXT：修正文字 | 声明修复表达但不改变原意 | 产生独立版本 | 不增加 MEANING 成分 | 可以沿用同一原意语境的评价 |
| MEANING：修改原意 | 声明改变正文表达的含义 | 产生独立版本 | 加入该 MEANING 成分 | 只使用完全相同原意语境的评价 |
| WIDTH：显示调整 | 调整卡片宽度 | 不产生正文版本 | 不改变 | 不改变正文评价语境 |
| 授权修改 | 实际修改存储部件或结构 | 产生新的基础存储版本，再计算正文 | 以新基础版本区分 | 不自动搬迁旧评价及资金执行 |

TEXT 的含义共享以“未改变原意”的类型声明为协议前提。反对 TEXT 不会自动把它改成 MEANING；需要纠正性质时另发明确的新候选，保留原声明与争议记录，不能追溯改写旧表态的语境。

采用、预览、更正类型、正文真假、正文价值是不同判断。采用一条更正不自动表示已阅该版本，也不自动表示赞同该正文的真假或价值。

## 3. 更正如何被采用、反对和替换

### 3.1 表态对象

| 用户实际指向 | 表态解释 | 是否直接参与更正采用判断 |
|---|---|---|
| 整条更正或其“更正关系”部件 | 赞同／反对采用这次修改 | 是 |
| 更正后完整正文 V | 赞同／反对该正文的含义 | 否；归入 V 的原意语境 |
| 更正记录中的正文、理由或片段 | 评价明确指出的内容 | 否 |
| 原消息的原文 | 评价原文原意 | 否 |

界面必须明确说明当前表态对象。反对采用 TEXT 不代表反对原文内容；反对采用 MEANING 也不代表赞同原意。对一条表态继续表态时，沿既有解析规则继承最终对象及其版本语境，本规则不另行改变表态链的方向算法。

### 3.2 个人与公共判断

1. 对同一条更正的采用表态，每个用户只取最新有效选择；整条更正和更正关系部件属于同一采用决定，片段评价不混入。
2. 公共推荐按支持、反对的用户人数判断，不按押注金额判断。反对人数大于支持人数时，该候选不参与公共采用；平票仍可参与竞争，并显示平票说明。
3. 本人的明确反对使该候选退出个人默认方案；明确赞同使它可参与个人竞争，即使公共推荐已排除它。合法性或基础版本不匹配等硬性条件不能被个人赞同覆盖。
4. 发布正文更正视为发布者对该更正的初始个人选择；之后的明确表态可以覆盖它。此规则不自动推导“已阅”。
5. 本人未对某候选作选择时，该候选按公共结果参与个人方案。公共推荐变化不覆盖已有的个人选择；个人方案仍可能因其他未明确选择的候选变化而变化。
6. “可以参与”不等于“正在采用”。同一位置或重叠片段的候选存在竞争；不重叠的字段、片段可以组合。
7. 对竞争候选，保持现有确定性顺序：本人选择优先；多个本人赞同中较新的选择优先；再比较公共净支持人数、支持人数；仍相同时按更正发布时间、编号稳定选择。公共方案不使用个人优先项，平票不虚构共识。
8. 预览被反对的候选，只解除阅览限制，不把它重新算成个人或公共已采用。

### 3.3 不采用的原因必须可区分

至少区分：本人反对、公共反对占多数、同处竞争未选中、基础存储版本不匹配、地址或内容不再可应用、等待授权的实际修改提案。

“未采用”是当前方案中的结果，不是消息被删除或永久失效。公共、个人两种采用状态分别展示；可应用性、公共资格、个人资格、竞争结果、预览状态不能都挤在一个 `valid` 标志里。

## 4. 正文已阅与确认范围

### 4.1 正文已阅的单位

正文已阅按“用户＋具体正文版本 V”保存，表示用户明确确认过该完整正文。原文、单独采用 C1、单独采用 C2、采用 C1+C2，分别记录。

1. 改变原意和只修正文字都产生独立正文已阅；共享原意评价不意味着共享已阅。
2. 保留现有产品前提：确认更正后正文前，先确认该基础存储版本的原文。不能暗中给未展示的原文补已阅。
3. 读过更正消息自己的完整记录，不等于确认过 M 的对应正文版本。
4. 读过 C1 和 C2 各自单独应用后的正文，不等于读过 C1+C2 的正文。
5. 读过 C1+C2 的正文，也不等于读过 C1、C2 各自单独应用后的完整正文。可以确认已展示的更正效果，不能把未展示的单独全文标为已阅。
6. 看过最终组合正文，不自动标记更正消息的隐藏理由、单独完整正文、其他回复或引用来源正文已阅。
7. 本人发送、投票、采用、关注、推荐、冷藏某消息，均不自动产生正文已阅。
8. 切回此前确认过的同一 V，恢复对应已阅；切到没有确认记录的 V，显示正文待阅。保留所有历史确认。
9. 仅改变宽度、归属、排列、显示／隐藏等，不撤销正文已阅；另外产生相应显示结果待确认。
10. 若提供手动标记未阅，它只覆盖指定 V 的当前阅读状态，保留历史已阅事实，不修改立场、其他版本和资金。

### 4.2 点击“当前正文已阅”实际确认什么

同一次确认可以包括：所见完整正文、实际展示的更正采用结果、所见类别统计及截止位置、所见归属路径和显示结果。操作前的提示与实际保存范围必须一致。

只有实际展示了某个附属消息完整内容，才可附带记录该附属消息的正文已阅，并保存“在哪个视图完整展示”的依据。仅看见更正后的效果或某类表态统计，只能确认效果，不能记录隐藏正文已阅。

组织成员在自己的展示位置确认。确认分类、总结等容器不确认全部成员；确认成员当前归属不确认容器正文、兄弟成员、旧归属路径或容器上的全部讨论。

### 4.3 影响确认与新增消息

影响结果确认按“受影响消息＋作用范围＋类别＋已确认截止位置”保存；需要逐条阅读的内容另有正文记录。

- 同一类别可以一次确认当前已呈现的一批影响，但不能永久确认未来新增同类消息。
- 赞同、反对、不同标注、发起结算、结算结果、终止结算分别确认；标注还区分具体标签。
- 具体发出的引用保留逐条地址；被引用可以按类汇总，仍须保存截止位置及事件身份。
- 新增、改向或被新执行替代的影响必须能再次待确认。对于旧事件产生的新状态结果，不能只比较最初发送时间。
- 使用服务端执行序号／结果依据和事件身份定义截止，不用客户端时间猜测，不把尚未加载的消息包含进去。
- 已读过一条影响消息的某版正文，不自动确认它在所有目标、所有语境下产生的后果；这些后果可在已充分展示时一并明确确认。

## 5. 影响归属：谁影响此消息，以及此消息影响谁

### 5.1 每个关系端点声明自己的作用范围

| 范围 | 匹配规则 | 典型用途 |
|---|---|---|
| 消息身份 MESSAGE | 同一消息身份；不依赖正文更正集合 | 关注、屏蔽、当前组织归属 |
| 具体正文 BODY | 同一 V；片段还须匹配 V 内的部件、范围 | 引用、回复、注释、证据所针对的具体文本 |
| 原意语境 MEANING | 同一 S，采用的 MEANING 集合必须完全一致 | 针对正文含义的赞同／反对、内容价值评价 |
| 更正采用 CORRECTION | 同一条更正的采用决定 | 对该更正是否合适的赞同／反对及其讨论 |
| 合同或轮次 ROUND | 同一固定执行目标及合同范围 | 发起、投票、终止、结果、分配 |
| 选择结果 SELECTION | 某显示方案的当前选择结果及其变化依据 | 更正不再采用、替换为其他候选、重新采用的原因 |

关系类型不能单独替代作用范围。比如“可靠”标注是在评价整篇含义还是某个引文，应按明确指向分别记录；不能把所有标注一律当成消息身份状态。关注、屏蔽和组织归属则维持身份范围。

新建回复、引用、注释、证据等内容关系，默认绑定实际所见正文／片段。需要讨论整条消息的身份或某个原意语境时，必须明确选择对应对象。引用若明确选择“跟随当前”，保存这一选择并标出后续变化；其中已经执行的表态和资金合同仍固定在发送时依据，不跟随漂移。

### 5.2 一个影响可以适用于多个正文版本

1. 消息身份影响适用于该身份的正文视图。
2. 原意影响适用于完全相同 S 的多个正文，包括其不同 TEXT 版本；不能只要求“当前包含某条 MEANING”。
3. 对 C 的采用影响，作为“所采用更正的相关影响”出现在所有包含 C 的正文视图中。它评价的是 C，不自动成为各正文的真假表态。
4. 当 C 未被采用，其讨论仍留在更正候选及历史记录中。若该讨论改变了当前选择结果，再通过 SELECTION 向当前消息说明变化原因。
5. BODY 关系默认只属于固定 V。另一版本即使文字相同，也不自动搬迁。若将来支持片段兼容继承，须另有可验证的地址映射及适用规则，不能按消息编号推断。
6. 影响可以连接多个对象；逐个端点记录范围，不能给整个关系只挂一个版本编号。

### 5.3 正反向查询必须一致

若关系 R 表示“来源 M 的 V1 引用目标 N 的 V2 的片段”，则：

- 从 M 查询“我影响了谁”，得到 R、来源 V1、目标 N/V2/片段。
- 从 N 查询“谁影响我”，得到同一个 R 及相同两端语境。
- M 改成 V3 后，不能把 R 的来源改成 V3。N 切换版本，也不能改写 R 的目标。
- 身份上的关联痕迹仍可查询，但要标注“来源其他版本”或“目标其他版本”，不能计入当前正文的内容评价。
- 若关系声明跟随当前，变化后的展示另有明确标识和确认；历史引用及执行依据仍可追溯。

新增外部影响不会撤销 N 自身正文的已阅。它可以增加 N 的影响待确认；只有 N 的具体正文版本变化，才重新查那个版本的已阅。

影响传播按明确的关系语义进行。不能因为图上可达某条更正，就把整条路径上的所有消息都归到该更正版本；普通回复、引用、表态不沿容器扩散到全部兄弟消息。组织结果改变才重算实际受影响的成员与归属路径。

## 6. 更正被反对后的状态变化

### 6.1 统一处理顺序

1. 保存新的反对消息及其明确对象，保留原执行语境。
2. 更新该更正最新个人立场、公共支持／反对人数及可应用性。
3. 分别重算公共、个人方案；同处重新选择候选，保留其他兼容更正。
4. 更新跟随方案的阅览；固定历史预览保持不动。显示变化与推荐变化分别说明，不能声称固定预览已被切换。
5. 对实际所见 V 查正文已阅；对 S 和其他端点范围重算适用影响，不移动旧关系。
6. 对发生变化的选择结果生成可重建的原因说明，保留导致结果的消息／表态及执行位置，在当前消息可见。
7. 更新当前影响待确认、选择结果待确认、其他版本提示及容器汇总。原有正文已阅不因新增反对被清除。
8. 资金只按原合同执行。重新显示、回退和预览不自动退款、迁移押注、重开轮次或重放历史操作。

原因说明由既有记录与新旧显示结果推导，无须每次查看都自动发布新消息或收费。刷新页面不能重复产生同一待确认变化；但“采用 → 排除 → 再采用”是新的状态变化，不能被第一次采用的确认永久覆盖。

### 6.2 具体变化表

下表中“被排除”表示本次反对已经改变相应方案中的资格或竞争结果，不表示每一票反对都一定触发回退。

| 情况 | 正文／原意变化 | 已阅变化 | 影响及其他状态 |
|---|---|---|---|
| 新增反对，但 C 仍被采用 | V、S 不变 | 正文已阅保留 | C 上新增反对待确认；不能显示“正文已回退” |
| 反对未采用候选，当前选择未变 | V、S 不变 | 不变 | 候选讨论更新；不凭空让当前正文待阅 |
| TEXT 被排除，无替代候选 | 只撤去其文字修改；保留兼容修改，S 不变 | 查回退后 V 的记录 | 同 S 的评价继续适用；保留更正争议，并提示撤去原因 |
| MEANING 被排除，无替代候选 | 撤去该含义修改，S 重算；保留其他修改 | 查新 V 的记录 | 新 S 的评价进入当前；旧 S 的评价归入其他语境；提示原因 |
| 有其他同处有效候选接替 | 重算 V、S；接替可能改变类型及原意 | 不从旧 V 搬已阅 | 说明“由 C 改为 D”，按新范围匹配影响 |
| 公共排除 C，本人明确赞同 C | 公共方案改变；个人方案中的 C 仍可参与竞争 | 本人实际 V 未变则已阅不变 | 展示个人与推荐不同；不假称所有用户都回退 |
| 本人排除 C，公共仍采用 C | 个人重算，推荐可保持 | 按本人所见 V 查询 | 两种结果及依据分别显示 |
| 更正重新具备资格并再次采用 | 重算 V、S，可恢复历史版本 | 同 V 的旧已阅可以恢复 | 新增选择结果变化仍待确认；旧关系按原范围重新适用 |
| 反对 WIDTH 后宽度回退／换候选 | V、S 不变 | 正文已阅不变 | 显示调整及原因待确认 |
| 用户固定预览已被排除的 V | 预览正文保持 | 只查询该 V 的已阅 | 标注未采用及原因，提供返回默认入口；不改变投票或合同 |
| 同时有多个更正被排除 | 对每一受影响位置重新选取，保留其他兼容修改 | 查询最终完整 V | 一次说明最终变化与全部依据，不能逐次误读成全部正文未阅 |

### 6.3 完整例子

同一基础 M.r 上有三个互不冲突的更正：T 是 TEXT，A、B 是 MEANING。

| 正文版本 | 原意语境 | 含义评价的共享范围 |
|---|---|---|
| 原文、T | 空 MEANING 集合 | 两者共享原意评价，已阅仍分别记录 |
| A、T+A | {A} | 两者共享 A 语境评价 |
| B、T+B | {B} | 两者共享 B 语境评价 |
| A+B、T+A+B | {A,B} | 两者共享组合语境评价，不继承仅 A 或仅 B 的评价 |

若正在跟随的正文是 T+A+B：

- 排除 T，得到 A+B，S 不变；正文是否已阅按 A+B 自己的记录判断。
- 排除 A，得到 T+B，S 从 {A,B} 改为 {B}；{A,B} 的评价保留在原语境。
- 排除 A、B，得到 T；原文语境的评价重新适用，不代表所有人因此赞同原文。
- 排除全部，得到原文；原文已阅可以恢复，但“为什么回到原文”的新影响仍需确认。
- A 的采用争议可出现在 A、T+A、A+B、T+A+B 这些包含 A 的正文相关记录中；它不等于这些正文的真假评价。

“读过旧版”与“已知这次为什么切回旧版”是两个状态。不得用恢复旧正文已阅来消掉新的切换原因。

## 7. 状态展示、汇总与筛选

至少独立维护以下信息，不使用一个“已阅／失效”同时表达所有含义：

| 状态 | 含义 |
|---|---|
| 当前正文已阅 | 这个 V 的完整正文是否确认过 |
| 原文前置确认 | 该基础原文是否已确认；只在需要时提示 |
| 当前影响待确认 | 当前 V／S／身份／合同适用的新影响 |
| 当前选择结果待确认 | 回退、替换、重新采用、归属或显示结果的变化及依据 |
| 其他版本待阅 | 已知候选或历史正文及其影响；按版本列出 |
| 成员待处理 | 当前容器实际成员各自的当前待处理汇总 |
| 个人与推荐差异 | 两种方案是否采用不同更正或结构，不等于正文未阅 |

当前正文的“与该版本上次确认一致”，与“自上次查看后默认选择曾发生变化”分开保存，不能让前者覆盖后者。

筛选口径固定为：

1. 消息卡片状态以实际正在展示的 V 为准。
2. 首页默认“待处理”以该用户默认方案为准，包含未确认的正文、原文前置、适用影响、选择结果变化，以及容器当前成员的待处理；固定预览不暗改首页口径。
3. 被排除候选和其他历史版本单独提示，不阻止“当前版本已确认”。另外提供明确的“全部已知版本待处理”入口，不能枚举所有可能组合并要求全部读完。
4. 其他版本未阅按正文版本计数，其他版本影响按相应分组另计；不能把正文数和影响消息编号混成一个数字。
5. 只有影响待确认时显示“正文已阅，新增影响待确认”；回到读过的版本时显示“正文已阅，本次切换待确认”。
6. “当前版本已确认”不表示赞同、不表示采用全部候选、不表示已阅所有成员或全部历史版本，也不表示结算完成。

## 8. 表态与资金合同

1. 更正采用判断、正文真假评价、正文价值评价是不同的执行对象。整条更正的采用表态使用更正对象；正文评价保存确切 V、S 及所选部件。
2. 全文含义的真假和价值评价均按 S 区分；TEXT 可共享同 S 的合同语境，MEANING 集合不同不能混入同一内容合同。对具体引文或部件的评价则按相应固定目标处理。
3. 支持／反对人数用于更正推荐；押注金额用于对应合同的结算。人数、金额、采用状态、结算结果分别显示。
4. 服务端验证版本可重建、更正确属该基础版本且组合兼容、S 与 V 一致、部件和片段可解析。不能只信任客户端提交的一串更正编号。
5. 发送时固定实际所见依据；发送期间推荐改变，不能把操作静默改到新正文。历史版本仍可讨论，是否可继续押注按该合同的访问规则判断。
6. 轮次、押注、执行立场、分配消息和服务端公开状态使用同一固定目标口径。前端分开显示不能代替服务端隔离。
7. 更正被反对、重新采用或用户切换版本，均不自动终止、退款或移动原合同。对旧结果的推翻按既有正式结算调整执行并保留依据。
8. 旧资金合同保留原目标、余额和执行历史。引入新版本目标时采用有版本的合同格式，不能按用户当前显示重写旧合同或猜测历史含义。

## 9. 保存、同步及旧数据

1. 已阅与影响确认保持个人数据，不生成公共消息、不收费、不改变公开序号或他人的阅读状态。
2. 新正文版本身份、关系端点语境、选择依据必须进入在线接口、缓存、离线导出和重放；刷新、分页、换设备及离线重开应得到相同归属。
3. 未加载某个版本或影响的依据时，显示“上下文待补齐”，不能默认当成原文语境、全部已阅或已失效。
4. 新格式必须区分“明确选择原文语境”与“历史语境缺失”。能据原引用和快照确定的旧数据才映射；无法确定的保留“旧记录，版本未明确”，不伪造全部版本适用或新正文已阅。
5. 旧的按类别永久确认不能直接代表新格式中无限未来的截止位置；只能依据可证明的确认时快照建立有限基线，其余保留旧确认来源提示。
6. 并发确认按同一范围合并已确认事件／推进合法截止位置，不因请求到达顺序退回旧进度。显式单版未阅操作单独保留操作顺序。
7. 私人已阅更新至少验证版本和作用范围确实存在，不接受无从解析的“全版本已阅”。这验证记录范围，不声称能证明人的阅读行为。

## 12. 验收场景

| 场景 | 必须验证的结果 |
|---|---|
| 同一组更正调整输入顺序 | V、S、已阅及归属不变 |
| 相同文字、不同更正来源 | 两个 V 分别可达、分别已阅与追溯 |
| 同一来源同时是个人和推荐 | 可合并入口，不制造重复版本 |

| 只读更正记录 | 不把原消息完整更正正文标已阅 |

| 先读组合，再看单独应用版 | 单独完整正文仍待阅，除非另有真实完整展示记录 |

| 更正反复采用和排除 | 不重复收费或退款，每次新结果可再次待确认 |
| 固定预览碰到公共反对 | 预览保持、原因可见，不自动投票 |

| 发送时推荐发生变化 | 固定所见依据，不静默改指向；非法组合拒绝 |
| 同一原消息不同 S 押注 | 新格式资金池、轮次、最新立场及状态查询均隔离 |
| 更正排除后结算、旧合同迁移 | 执行原合同，不自动转本金、清零或猜测历史含义 |
| 旧记录缺语境、分页缺上下文 | 明确未知／待补齐，不推断全版本适用和已阅 |
| 并发确认、刷新、离线重开 | 不退回进度，不重复变化提示，版本及影响可复算 |

## 13. 本次实现及迁移边界

| 调整 | 实现 |
|---|---|
| A1、A4、A8 | `packages/core/src/body-versions.ts` 统一 V、S、端点与合同键，正文键和原意键使用不同前缀；服务端验证基础版本、更正版本、完整组合及片段。真假和价值统计、轮次和投入按明确范围保存。 |
| A5、A9 | 候选的可应用性、排除原因与是否采用分开；保存选择结果快照及有限变化事件。回到已阅旧版时正文恢复已阅，本次回退仍待确认。 |

| A2、A7 | 版本入口与导航按来源身份区分，提供固定预览和已确认／被引用历史组合；当前待阅与全部已知版本待阅分开，其他正文数与其他影响数分别提示。 |

兼容转换统一放在 `apps/migrate`。数据库第 25 次迁移与阅览文件第 4 版使用同一转换规则；主程序不根据旧消息级 READ、类别永久确认或缺失的表态语境猜测新版已阅。

- 转换前的消息、修订、执行日志和幂等结果保存在 `version_context_backups`；原始签名及请求输入保持原样。转换后的增量通知不含资金流水。
- 旧私人确认保存在 `reading_migration_archive`。能证明为原文完整确认的记录映射到原文 V，其余保留“历史确认范围未明确”，不会扩大到新版本或未来同类事件。
- 已有押注、轮次、执行立场、余额和账本不重写。旧合同继续通过其明确轮次或原固定地址操作；新正文合同使用新版范围，不自动迁移旧本金。
- 在线发送固定实际所见依据；在更正版上选取新更正但无法可靠映射基础坐标时，要求切回原文重新选择。当前界面提供固定引用，未提供“跟随当前引用”入口。
- 缺少历史上下文时保留版本身份并显示“上下文待补齐”；不会用当前文字替代缺失历史。不会枚举所有理论组合。
