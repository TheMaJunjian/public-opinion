# 公论第一版规范

公论是一场持续的会议。用户通过发言、举证、表态和组织讨论推进会议，以贡献点承担成本、参与对赌、获得贡献收益。结算产生规则上的共识，共识可以继续被讨论和推翻。

1. 发言、关系、修改、结算、分配、委托、治理和运营操作都以消息表达。消息内容除了不同格式的内容数据，还包括相关消息的显示方式。内容数据的格式可以是文本、网页、可运行代码等。

2. 消息具有独立身份、发送者、时间、内容及版本。消息由不同部件组成。引用可以指向整条消息，也可以指向消息部件，比如文本片段、字段、关系类型、成员角色、规则条款、程序输入输出和流程步骤。关系中的成员位置、其中的引用值、被引用对象都是部件，分别可被指向。引用明确跟随当前内容还是固定历史版本。

3. 关系也是消息，可以连接多个消息或部件，也可以被引用、回复、标注、赞同、反对和修改。注释、引用、回复可附带新内容，也可关联已有内容；疑问、回答、证据等由关系类型及标注表达。关系类型及其作用可以扩展，对关系的表态保留其实际目标与语义。

4. 分类将讨论同一问题的消息放在一起；归并将整理好的显示结构保存下来；总结以总结内容覆盖讨论过程；排列将并列消息放在一起显示。组织关系可以嵌套，同一消息只能在一个组织中，这个组织可以在另一个组织中。成员位置的变化作用于对应组织，原消息内容的变化作用于引用其当前版本的位置。

5. 消息发送后直接显示。总结发送后产生覆盖效果；反对覆盖的消息直接显示并取消覆盖，恢复被组织内容的显示。恢复时保留其他仍有效的组织关系。被反对、覆盖、冷藏或取消效果的消息仍有存在痕迹，可以查看、引用和投票，痕迹与原消息使用同一身份。反对本身也可以被讨论和反对。

6. 讨论以非线性关系组织，赞同与反对分区显示。消息的字体、背景、位置和推荐顺序可以不同，按推荐投入及价值规则确定；具体对赌金额不直接决定推荐程度。多个显示方案关联到内容消息，用户查看关联、预览方案并选择要投票的显示方式。

7. 内容和显示都可以修改。任何人都可以发送消息提出对任何部分的修改；修改提案直接显示，目标内容在讨论确认并获得生效授权后更新。消息保留身份和修改历史，内容更新引起相应显示更新；已有表态、押注和执行记录保留发生时的内容依据。

8. 发送消息至少支付协议费，用于公论运营。用户可以另行投入贡献点推荐本消息，或选择自我赞同和参与对赌。仅支付协议费即可发言，不自动自赞、推荐或押注。协议费、推荐投入和对赌资金分别记录；推荐表示希望获得关注，不等于赞同内容。

9. 对内容发送赞同或反对，即发起或参与针对该内容的结算，开始对赌过程。没有形成对赌双方时，不成立双方对赌资金池。结算消息明确讨论对象、立场和资金范围，本身也可以被讨论、标注、表态和评价。

10. 用户发送终止结算消息，按规则触发终止。初始采用单人触发、固定等待，等待时长由规则规定，同轮重复请求不重置计时。终止时统计目标及本轮范围内截至终止时刻的赞同、反对资金，采用执行该行为的当前版本规则，生成分配消息。终止条件和分配规则都可以修改。

11. 未形成双方对赌时，不作胜负分配。形成双方对赌后，初始按赞同、反对的资金总额判定胜负，金额多的一方获胜；胜方按出资比例分配赌池，败方损失本次全部本金，平局返还各自对赌投入。对赌损益与贡献收益分别计算，押错者仍可因有价值的贡献获得收益。结算结果可以被后续讨论推翻，按规则调整被推翻轮次的资金分配，并保留新旧结果的关联。

12. 低质量评价针对用户发送的具体消息，由其他用户通过讨论和投票确定。成立后按通用处罚规则扣除消息发送者的贡献点，计入运营收入。评价可以不成立，也可以在成立后被推翻；推翻时处理相应评价对赌的分配更新，以及发送者的处罚调整或平反。“这次对赌无意义”就是对那条结算消息的低质量评价，这项评价不改变原对赌已分配的资金。

13. 运营收入留足运营所需后，按贡献分配。贡献归因依据消息的标注、关系类型及其讨论结果；相反标注构成对赌，标注结果变化时按规则更新归因。相关讨论的热度与有效参与是贡献依据，后续参与费用和相关运营收入可以回流早期贡献者。同期有价值的发言应比单纯赞同获得更高收益；缺乏新意和认可的晚发言可以低于早期赞同。时间、逆风、证据、新意和认可等权重由规则决定，分配以实际可用收入为限。

14. 分配消息是规则运行的结果，记录资金来源、可分配数量、适用规则和程序版本、输入及参数，以及每笔金额、接收者、原因和所依据的消息。用户据此讨论规则及其依据。对赌分配、运营分配、委托报酬和处罚分别归因；每次调整保留对应的执行和资金记录，同一笔资金不重复支付。

15. 委托消息约定任务与报酬，完成者发送完成说明并关联委托，按讨论结果和规则支付报酬。完成认定被推翻时，按规则调整已支付报酬。委托报酬与关于委托的对赌资金分别记录。

16. 所有规则都可以通过消息提出修改。宪法形成前，消息和规则的修改生效需要项目发起人的允许，其操作公开并可被质疑；宪法形成后，由宪法决定权限和程序。代码、制度与流程可以提交、讨论和修改，程序规则的生效通过代码修改与项目更新实现，提案、确认、授权和发布版本相互关联。

17. 第一版运行一个地区和一套贡献点账本。地区与程序版本分别标识，地区升级版本可以延续消息和账本。消息来源、贡献点所属账本，以及每次行为所采用的内容、程序和规则版本可追溯，用户在当前运行版本的行为按该版本处理。

18. 用户可以注册登录、确认身份和操作来源，查看自己及他人的发言、立场和参与记录；进行关注、通知、屏蔽、冷藏、已读与未读标记。讨论支持搜索、排序、筛选、线性与非线性浏览、聚焦消息和沿关联追溯，以及键盘和手势快捷操作。用户与消息的贡献、收入、认可和相关热度可以统计、比较和排序。

19. 贡献点可通过按规则发放、充值、贡献分配、对赌收益和委托报酬取得。账户展示可用、锁定、负债状态及收支明细，资金变动能追溯到相关消息。消息、关系、版本、操作、结算和资金记录可以查询、按范围导出、重新阅览和复算。
