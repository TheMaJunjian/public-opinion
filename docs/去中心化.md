**当前架构状态**

当前是中心化 Web 原型：

- 前端：package.json 是 Vite + React。
- 后端：package.json 是 Express + TypeScript。
- 数据库：schema.prisma 是 PostgreSQL + Prisma。

**1. 硬删除会破坏未来可审计性**

现在删除分类时会物理删除消息和分类：

topics.ts

```ts
prisma.message.deleteMany({ where: { topicId } }),
prisma.topic.delete({ where: { id: topicId } }),
```

这和未来“所有事件可追溯、可复算”冲突。去中心化前置阶段不应该物理删除关键内容，而应该：

- 追加 `TOPIC_ARCHIVED` / `TOPIC_DELETED` 事件。
- 保留原始 Topic、Message、Relation。
- 前端默认隐藏被删除/归档内容。
- 审计导出仍能看到完整历史。

**优先级：高。**

**2. 关系 PATCH 是直接改旧状态**

现在分类/总结关系可以直接更新 `targetRefs`：

relations.ts

```ts
const updated = await prisma.message.update({
  where: { id: relationId },
  data: { targetRefs: data.targetRefs },
```

这对普通 Web 没问题，但对事件重放不友好。未来应该改成：

- 不直接覆盖旧关系。
- 追加一个 `RELATION_UPDATED` 或 `RELATION_SUPERSEDED` 事件。
- 或创建新的 RELATION 消息，带 `supersedesRelationId`。
- 当前有效关系由 replay 规则计算出来。

**优先级：高。**

**3. 缺少 EventLog / AuditLog 表**

当前 schema 只有 User、Topic、Message 等基础模型：

schema.prisma

- `AuditLog` / `EventLog`
- `RuleVersion`
- `PointTransaction`
- `StateSnapshot`
- `EventBatchHash`

去中心化前置阶段至少要先加：

| 模型 | 用途 |
|---|---|
| EventLog | 记录所有关键动作 |
| RuleVersion | 记录每次规则版本 |
| PointTransaction | 记录贡献点变动 |
| StateSnapshot | 可选，用于定期快照 |
| EventBatchHash | 可选，用于未来上链锚定 |

**优先级：最高。**

**4. 业务逻辑还不是 replay-friendly**

```text
API 请求
  ↓
校验
  ↓
生成事件
  ↓
applyEvent(event)
  ↓
写入派生状态 / 当前状态
```

也就是说，不是接口直接“改结果”，而是接口先“产生事件”。

短期不用搞完整 event sourcing，但至少新经济模块要这么写：

- 贡献点
- 下注
- 结算
- 挑战
- 收益分配
- 规则变更

**优先级：高。**

- `RuleVersion` 表。
- 每次结算记录使用的 `ruleVersionId`。
- replay 时根据当时规则复算。
- 新规则延迟生效。

否则未来无法证明“某次结算到底按哪套规则算的”。

**优先级：中高。**

现在登录是与会者名密码 + JWT：

auth.ts

- 与会者公钥字段。
- 操作签名。
- 事件签名。

### 建议节奏

```
本周：  阶段 A（基础设施补齐） → 打通 RuleVersion + PointTransaction

```
