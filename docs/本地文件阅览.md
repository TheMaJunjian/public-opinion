# 本地文件阅览

局域网小组可以从“阅览 → 选择共享文件夹”创建或加入会议。每台电脑选择同一个可读写的共享文件夹后，即可同时发言、回复并自动同步。已有的普通本地消息文件也可用作会议起点。[离线会议文件交换](离线会议文件交换.md)

使用云端存储时，成员仍在公论里发言和回复。消息由浏览器直接与所选平台同步。

- **WPS 多维表格**。在“打开讨论或文件 → 云文档 → 使用 WPS 云文档”粘贴整段分享文字，点“打开讨论”。需要登录或申请访问权限时会自动进入 WPS，完成后用浏览器返回，再点“打开讨论”。每份云表各自保存一场讨论。
- **新建 GitHub 讨论**。在“阅览 → Git 仓库 → 使用 GitHub 仓库”选“新建讨论”，填写名称，用 GitHub 授权。可以同时新建个人仓库，也可以粘贴已有仓库地址。仓库需要启用 Issues。同一仓库可以有多场独立讨论，每场有自己的 Issue 链接。[部署时启用 GitHub 登录](../README/云服务器部署.md#启用讨论仓库的-github-登录)
- **加入和发言**。组织者在“会议交换”复制加入信息，成员在“进入已有讨论”粘贴这条链接。公开讨论支持免登录阅读。发言时使用仓库所有者、组织成员或受邀协作者的 GitHub 账号。内部讨论可使用私有仓库并邀请参与者。[邀请仓库协作者](https://docs.github.com/zh/repositories/managing-your-repositorys-settings-and-features/repository-access-and-collaboration/inviting-collaborators-to-a-personal-repository)
- **同步**。每次发送只把这次新增的发言和回复关系写成一条 GitHub 评论。GitHub 确认后即可继续发言。首次进入会读取当前讨论；已授权的设备恢复联网后从本机保存的评论位置补读。公开讨论在页面重新加载后仍可匿名续读，GitHub 的匿名接口可能重读时间边界上的评论，公论会按编号去重。页面重新加载后要继续发言，可在“会议交换”中重新连接 GitHub。公论将评论作为追加记录，请在公论里发言和回复，并保留 GitHub 上的原始记录。手动编辑或删除 Issue 正文、发言评论，可能使新加入者与已有成员看到不同的历史。
- **归档**。组织者可以在“首次使用 GitHub”下载归档工作流，保存到仓库默认分支的 `.github/workflows/gonglun-archive.yml`，并允许工作流提交到默认分支。单份归档上限为 32 MiB。每场讨论会在后台归档到 `gonglun/discussion-<Issue编号>.jsonl`。需要补存已有讨论时，可在 Actions 手动运行归档并填写 Issue 编号。[下载归档工作流](../frontend/public/gonglun-archive.yml)
- **使用个人令牌**。要限定到特定仓库，可在“首次使用 GitHub”查看步骤。参与发言需要给令牌授予所选仓库的 Issues 读写权限，阅读私有讨论可用 Issues 只读权限。[GitHub 令牌说明](https://docs.github.com/zh/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)
- **退出**。点“退出云端讨论 → 退出并清除”，可清除本浏览器内的云端讨论缓存、发言人和 GitHub 令牌。勾选“同时前往 WPS 账号中心”，可在官方页面顶部选择“退出账号”或“切换账号”。[WPS 账号中心](https://account.wps.cn/usercenter/)

公论以消息、证据、表态和组织讨论为主要功能。知乎导出程序及本机文件阅览仅是用户可选的本地辅助，不上传文件、不发布为公论消息。首页以公论为主，本机阅览保持为次要入口；相关选项与同步详情默认折叠。

新版 [personal-data-exporter](https://github.com/TheMaJunjian/personal-data-exporter) 在所有目录统一导出精简 `gonglun-view-3` v5。正文只存于 `parts`，读取时从部件还原界面需要的 `content`，不再重复保存。`gonglun.json` 不附带整份 `zhihu.archive`、旧 `overrides` 或 `localOperations`；保留消息、作者、时间、关系和少量来源身份信息。

从导航栏“阅览”或首页“打开讨论或文件”进入，在“本地消息文件”中选择 JSON 即可打开。精简文件仍按来源识别为知乎文档阅览，可使用线性、非线性视图，并在本机发送回复、赞反、更正及组织消息；操作保存为公论原生消息，不把旧来源封装写回文件。

“下载阅览文件”可生成独立快照，也可选择以前下载的精简阅览文件，点击“更新文件”合并当前原文和本地原生消息，再保存到原文件。重复更新不重复添加消息，兼容的较长本地消息历史会保留；不同来源、缺失原文或本地历史分叉会停止合并。保存前还会核对目标文件与所选旧文件是否一致。此过程完全在本机完成；单个 JSON 会完整写回，按新增内容追加保存使用下方的目录关联。

在 Chrome 或 Edge 中点“阅览”，到“本地消息文件”分区展开“知乎导入”，选择“关联知乎导出目录”，可持续读取该目录的 `gonglun.json`。本人作品和收藏应分别关联各自目录，收藏选择 `collections`。在前台每 5 秒或切回页面时检查更新；已打开文档和折叠状态沿用同一份本机缓存，更新失败保留当前视图。本地新增内容以原生消息增量追加到同目录的 `gonglun-local.ndjson`，格式为 `gonglun-native-messages`，不使用旧的 `overrides` 或 `localOperations` 日志。重新导出原始资料后，这些本地原生消息继续合并保留；旧日志不会被当作新消息自动迁移。

导出器的增量采集、续传继续使用 `checkpoint.json`、`checkpoint.journal.ndjson` 和原始采集档案；这些采集资料独立于精简阅览文件，不要只凭 `gonglun.json` 恢复采集任务。

已有知乎导出可在导出器的 `platforms/zhihu` 目录运行：

```sh
npm run migrate:view -- /path/to/gonglun.json --in-place
```

脚本只处理指定阅览文件，原地删除旧来源封装和重复正文；不处理采集检查点，不请求网络。省略 `--in-place` 会另存 `.compact.json`，可选输出路径不会覆盖已有文件。

已放弃的旧知乎整理缓存会在新版首次打开阅览缓存时清除，包括旧目录关联和折叠状态；普通公论文件缓存保留。需要时重新关联目录即可。旧版原始归档或整理文件仍能直接读取，但不迁移此前浏览器中的知乎整理记录。

正式构建会准备离线界面。阅览窗口显示“离线可用”后，断网仍能重新打开本站及本机文件。清除网站数据会移除离线缓存和本机阅览记录，磁盘文件不受影响。离线功能需要 HTTPS 或 localhost，开发服务器不启用。
