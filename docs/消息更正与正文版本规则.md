# 消息更正、共享状态与历史依据

更新日期：2026-10-26。本规则替代[原复杂方案](history/消息更正与正文版本规则-20261025.md)，旧文档仅作设计记录。代码修改不代表已经部署或已对实际数据库执行迁移。

## 1. 产品边界

更正只用于修正文字，仍由投票决定采用，作者不能单独确定。“修改原意”从更正中删除，改变观点、事实主张或结论应发送独立正文，再新建一条对原消息的引用；引用支持自定义说明，例如“修正原意”或“更正”。正文和引用分别按普通消息计算协议费和贡献投入，预估与实际扣点均须包含引用。保留 TEXT 文字更正和 WIDTH 显示调整。

更正 C 是普通消息，有自己的已阅、讨论、表态、资金和结算，不与原消息 M 合并。M 的原文、单条更正效果和兼容组合是 M 的不同显示版本，共享 M 的已阅、讨论、表态和资金归属。

## 2. 版本与采用

存储版本 M.r 保存实际内容；显示版本保存基础 M.r 和采用的更正编号、各自存储版本。这些身份用于重建历史正文、引用和阅读依据，不为每个组合建立新的已阅状态或资金池。来源不同但同文的版本仍可追溯，切换版本不改变已阅。

更正针对原消息明确部件或原文片段，不把更正后坐标当成原文坐标；无法可靠映射时要求切回原文重新选择。不重叠且有效的更正可以组合，重叠候选沿现有确定性顺序竞争，不枚举全部组合。旧更正不自动套到新基础存储版本。

每人对 C 的采用决定取最新有效选择。公共推荐按支持、反对人数，反对超过支持则排除，平票不虚构共识。个人明确选择可与公共推荐不同，合法性、地址和基础版本限制不能被覆盖。发布更正保留初始个人选择行为，不自动视为已阅；预览也不等于采用。

## 3. 首次已阅与后续提醒

首次把 M 标为已阅前，必须确认原文以及当时已经存在的全部更正消息已阅，包括被反对、未采用、竞争落选及显示调整。确认更正类别的影响不能代替阅读 C 本身。

如果仍有 C 未读，确认原文只保存“原文已阅”的进度，不提前把 M 标为已阅，也不暗中标记 C 已阅。全部前置满足后，可以在任一显示版本确认 M。服务器按完整更正集合复核，不能只信任前端加载的候选。

M 首次已阅后，新增更正、投票、结算、采用或推荐变化按普通消息产生新的待确认提醒，M 仍然已阅。阅读 C 只确认 C 自身及明确呈现的关系影响；确认 M 的影响不冒充已读 C 正文。提醒确认只覆盖具体事件及版本，后续轮次或同类事件仍要提醒。

手动未阅作用于整条 M，各显示版本同步；首次确认时间、所见正文及历次确认事件仍保留，再次阅读不重新施加首次门槛。界面区分“消息已阅”和“已阅且无新提醒”，不再分列其他版本待阅。

## 4. 讨论、影响与表态归属

| 对象或行为 | 归属与处理 |
|---|---|
| 对 M 的回复、讨论、真假及价值表态 | 归 M，各显示版本继续可见并计入同一消息 |
| 引用 M 某个显示片段 | 归 M，另保存所见版本和片段作为引用依据 |
| C 及对 C 的投票、回复、结算 | 归 C，同时向 M 提供更正相关提醒 |
| 对 C 整条或更正关系表态 | 参与 C 的采用判断 |
| 对 C 理由、正文片段表态 | 归具体部件或片段，不冒充整条采用票 |
| 改变原意的新主张 N | 独立归 N，可关联 M，不计入 M 的表态和资金 |

关系保留实际端点、作者和历史引用。M 的讨论及影响不按所选更正集合过滤。对表态继续表态沿既有链式目标解析规则执行。

## 5. 更正被反对后的状态变化

| 变化 | 正文和选择 | 已阅与提醒 | 资金与记录 |
|---|---|---|---|
| C 被排除 | 撤去 C，其余兼容更正继续参与，或采用替代候选 | 已阅 M 不变；首次未阅仍须读 C；新增变化提醒 | 保留 C、票、旧组合；不回滚投入 |
| 本人反对、公共仍采用 | 个人排除，推荐可采用 | 提示个人与推荐差异 | 普通消息规则 |
| 公共排除、本人赞同 | 合法时个人可采用 | 推荐变化产生提醒 | 不改写历史票和钱 |
| 后续又投赞同并重新采用 | 按最新选择重算 | M 仍已阅，新变化可再次确认 | 新投入按普通轮次执行 |
| C 产生新一轮结算结果 | 普通结算；采用仍按现有人数规则 | M 不变，结算事件提醒 | 按该轮固定合同执行 |
| C 失效或基础版本变化 | 不自动迁移旧候选 | 保留阅读事实和旧正文，提示变化 | 旧合同仍按原依据结算 |

反对更正不表示赞同原文，也不改写过去的票。金额结算与按人数推荐是不同判断。允许多轮投不同的票：公开选择取最新有效表态，历次投入和结果分别保留。

## 6. 资金与历史依据

新引用使用 MESSAGE 归属，可附带所见显示版本作证据，该证据不参与整条消息资金地址。M 的文字显示版本共享普通整条消息真假、价值投入目标。C 使用自己的普通消息目标，不增加更正专属退款或补偿。

明确片段与整条消息仍遵守普通协议中的不同目标规则。历史轮次、押注、已执行表态、明细和签名保留原始目标；不因共享展示合并旧合同或重算已结算收益。界面可汇总归属，执行时须使用该轮固定依据。

## 7. 旧数据迁移

兼容集中于独立迁移程序及阅览文件迁移模块，运行时只确认新共享已阅格式，不猜测旧版本已阅。

- 旧“修改原意”更正保留独立消息编号，直接转为普通正文，不产生新修订、不保留更正修订链；另新建一条引用消息，来源是该正文、目标是原消息，自定义说明为“修正原意”。
- 有明确版本依据的旧已阅合并为 M 的共享状态，最近显式未阅优先；曾确认过则保留首次确认依据。未知语境保留为未知，不补造原文或所有更正已阅。
- 原逐版本阅读事实完整备份，原确认历史不删除。具体影响确认不扩张为永久确认未来事件。
- 旧押注、轮次、执行资金目标、签名原文、请求输入和既有账本不改写。仍需核对的原引用与合同正文单独冻结为依据，不作为新正文的修订。转为普通正文时，协议费按当前规则核算，多扣返还、少扣补扣；已有真假和价值投入及其合同保留。新增引用另扣普通协议费及 1 点价值投入，所有差额追加独立流水，允许迁移后的可用贡献点为负数。预检列出引用消耗、正文费用差额、净补扣或返还以及迁移后余额，不因余额不足阻止迁移；日常发消息仍按普通余额规则处理。迁移幂等，第二次不重复新建引用或调整贡献点，也不执行历史到期结算。
- 阅览文件升级为格式 5，保留原文件；带执行记录时追加升级记录，保持可重放和资金校验。离线阅览文件只转换展示结构，不能执行交易或伪造扣点；实际数据库迁移才发布和计费新引用。

## 8. 实施顺序和验收

1. 更新规则和共享引用、阅读契约，保留历史重建。
2. 删除“修改原意”写入能力和入口，更正沿用普通消息、多轮结算。
3. 统一 M 的讨论、最新表态及资金展示归属，保留历史合同执行目标。
4. 实现首次原文加全部更正门槛、共享已阅、手动未阅及后续提醒。
5. 增加数据库与阅览文件迁移，核对历史、签名及资金依据，独立记录授权的费用差额和新引用消耗。
6. 补齐前后端和迁移回归测试，运行完整测试与构建。

验收重点：落选和被反对更正参与首次门槛；读 M 不隐式读 C；后加更正和多轮结算不重置 M；切换、恢复历史显示共享状态；不同显示的新投入共用目标，C 与 M 独立普通结算；历史组合可重建；迁移幂等，补扣、返还及负余额正确，历史资金合同和签名依据不变。
