# 界面主题

三个风格选项共用组件、操作状态和业务逻辑：`gpt`（原版）、`gpt-arena`（gpt6astra-max · 议事厅·卡牌）、`opus-paper`（opus5.5-high · 案卷·印信）。两种 Opus 已合并；旧 `opus` 偏好自动归入 `opus-paper`。`html[data-appearance]` 保存完整选项，`html[data-theme]` 仍为 `gpt` / `opus`，提供覆盖所有窗口的基础颜色。导航“风格”弹窗保存到 `gonglun.theme`，默认 Opus；切换不重建工作台。

两套新风格的跳转入口位于“导出”右侧。`MessageJumpControl` 在点击时读取剪贴板，识别完整消息 ID 后沿用原跳转流程；其他文本全选以便编辑，剪贴板不可用时可手动输入。旧风格保留原来的内联输入框。消息标题旁不再显示 L0–L3 数字标记，投入外观仍由原来的档位规则控制。

三种风格只改变显示，功能及交互共用实现。控件布局统一在 `theme.ts` 的 `THEMES[].layout` 中设置：`messageJump` 的 `toolbar` 为顶部，`view` 为视图工具栏的导出右侧；两处均使用 `MessageJumpControl`，支持剪贴板跳转及手动输入。`relationControls` 的 `toolbar` 为顶部，`desk` 为右侧操作台，均使用 `RelationChoices`。组件通过 `useThemeSettings()` 读取位置配置；不要根据风格名称切换业务行为。新增风格时保留 `ThemeDefinition` 的类型检查，配色和材质继续放在相应 CSS 中。

左右区域保持独立滚动，不提供冻结开关。当前区域到达边界后只把剩余距离交给整页，不自动滚动另一侧；手机缩放后的页面移动仍由原来的页面边界处理。

- `gpt.css`：原深色的颜色、字体、推荐显著性。
- `opus.css`：暖纸的对应变量。
- `shared.css`：两套主题共用的控件结构、状态和动画。
- `opus-layout.css`：暖纸专用的导航、操作台和卡片外观。
- `theme.ts` / `ThemeSwitcher.tsx`：偏好保存和切换入口。
- `message-skins.css`：新风格共用的载体外观规则、选择状态和风格弹窗。
- `opus-paper.css` / `gpt-arena.css`：两套新风格各自独立的配色和外观。后续 Opus 调整 A 时修改前者；不要复制样稿交互或业务状态。
- `specimen-skins.css`：直接对应样稿的材质、装裱、云纹角花、金属包角、卷轴签、玉牌与框架织纹；A/B 分别限定在 `data-appearance` 下。`StakeTierBadge.tsx` / `GraphSkin.tsx` 提供不接收点击的装饰层，SVG 始终使用真实端点和容器坐标。
- `specimen-layout.css`：右侧 01–05 分区、16 种关系的五组入口、费用明细和发送条。`RelationChoices` 复用原来的切换动作；原版显示在顶部，新主题显示在右侧。
- `ThemeTierPreview.tsx`：风格弹窗中的四种载体 × 四档预览，复用正式装饰组件。`useSkinMotion.ts`：只在已知档位变化时播放一次动效，最多同时 4 个；视口外、减少动效或超过 200 个已挂载消息时跳过。
- `ThemeIcon.tsx`：议事厅的仲裁、治理、账户、所含消息与工具按钮采用同一套线性图标。案卷使用独立的细墨线图标：赞反装饰为方印勾叉，贡献点为方孔钱纹，统一线宽并继承文字颜色。关系类型入口仅治理组（提案、委托、代码、运营）显示图标，其余类型显示纯文字，图形定义保留在 `paperShapes` 中备用；原版保留原符号。只转换程序定义的界面标签，消息正文保持原文。

议事厅也覆盖旧组件的浅底配色变量，仲裁轮次、统计、历史记录及状态提示使用对应的深色背景与亮色文字；补充弹窗时同时检查正文、数字和禁用状态，避免浅底与浅字混用。

原版的弹窗遮罩内、独立 dialog/tooltip、结算历史和 `.record-panel` 记录面板也统一覆盖旧浅底变量，保留状态色并配套提高文字对比。新增独立弹窗应保留 dialog/tooltip 语义；复用旧配色的内嵌记录面板使用 `.record-panel`，加载、空态和错误状态也应沿用。

样稿中的正文、边与标签、附着装饰、框架分别接到现有真实载体。`data-skin-*` 只用于外观，不改变事件、业务端点或折叠入口；装裱留白改变卡片尺寸后，由现有测量机制重排。赞反图标与数字区域、更正单击/双击、标注折叠和记录全部沿用现有行为。已阅、选中、定位、推荐显著性和框架虚实线仍保留；不新增内容高度上限。

投入档位按单条消息上所有参与者的真假押注与价值押注（各自正反双方）相加：第一档 L0 < 1000，第二档 L1 为 1000–99,999，第三档 L2 为 100,000–999,999，第四档 L3 ≥ 1,000,000。高档表示多人集中投入的规模，不是个人每日签到等级。推荐投入与协议费不计入；推荐显著性继续单独显示。未知统计不伪装成零投入。聚合装饰取组内最高档位，不因合并计数而升档。规则及图例范围统一由 `utils/stakeAppearance.ts` 导出，外观在 `stake-tiers.css`；修改规则需要同步介绍文档和边界测试。所有风格共用统计门槛，仅外观不同。

两套新风格通过轮廓、层叠边框、角饰和线宽区别档位，原版深色保持旧外观。正文、边与标签、附着装饰、容纳框架保持真实载体及交互。风格弹窗提供四档只读外观示例。选中消息卡抬高到有向边与边标签点击区上方，取消选中恢复；外层卡片组不建立阻止抬高的堆叠上下文。

议事厅使用细金属边、局部紫色角饰、金色包角逐档增强，正文装裱厚度为 0 / 2 / 3 / 5px。卡片显示实际投入合计，悬停说明正反双方统计口径；不显示 L0–L3 编号。整条选中使用浅色外轮廓与固定占位的“✓”，边框厚度不随选择改变，避免消息图重排；统计未加载时仍保留选择提示。材质保留在内侧，片段继续使用蓝色提示。该风格的 `gpt-arena.css` 在共用载体样式之后加载，所有规则限定在 `data-appearance='gpt-arena'` 下。右侧空暂存区隐藏无效的移入按钮，空来源/目标保留名称与数量，有内容自动恢复；宽侧栏的关系分组排为两列，窄侧栏保持单列。风格弹窗可滚动，关闭按钮始终保持可见。原版与案卷布局不受这些覆盖影响。

新增功能只写一份组件。优先使用两套主题已有的语义变量：`--surface-page/card/panel/hover`、`--text-primary/secondary/muted`、`--border-default`、`--selection-accent/bg`、`--fragment-accent/bg`、`--location-accent`、`--font-reading`。需要新的视觉语义时，在两个主题文件里同时定义。已有 `--ink-*`、`--surface-*`、`--line-*`、`--shadow-*` 的色值后缀是旧界面的兼容标识，不代表运行时颜色；保留这些区分是为了准确恢复旧风格。后续改动相应控件时可逐步归入语义变量。

不要在组件里按主题分叉业务逻辑，也不要复制一套页面。不要把主题作为组件的 React `key`。弹窗不能再写死背景或文字颜色；SVG 的可见填充和描边也应使用变量，但黑白遮罩属于图形算法，不随主题更改。

新增弹窗复用 `dialogStyles` 和 `--dialog-*` / `--button-*` 变量。引导窗口阴影与目标区域高亮分开：`--guide-shadow` 用于窗口，`--guide-target-shadow` / `--guide-target-ring` 用于操作目标，禁用条件始终由功能代码决定。

暖纸和两套新风格的关系标签底牌复用文字测量结果，原版 GPT 隐藏底牌。切换完整风格选项时 `useGraphOverlays` 会重测文字尺寸，连线、点击区域及关系记录继续共用同一套数据和处理函数。

透明颜色使用 `color-mix(in srgb, var(--fragment-accent) 20%, transparent)`，不能在 `var(...)` 后拼接十六进制透明度。字体变化引起的消息尺寸由现有 ResizeObserver 更新，推荐投入的数值规则不变。

检查新增界面时覆盖两套主题的常态、选中、禁用、已阅及弹出状态；`theme-contract.test.mjs` 会检查变量成对定义和遗漏的变量引用。

Opus 后续样式在 `opus-paper.css`，于共用载体样式之后加载；所有细化规则同时限定 `data-theme='opus'` 与 `data-appearance='opus-paper'`。类型造型使用独立的 `skin-type-ornament`，即使 L0 或统计未知也可显示；投入装裱仍由 `stake-skin-ornament` 控制。选中使用不占布局的外轮廓，原关系记录及框架虚实线保留。框架层号直接复用已有深度，不参与组织或布局计算。超过 200 条已挂载消息时，`useSkinMotion` 标记 `data-skin-dense`，隐藏角花和外晕并停止动画。

`opus-dialogs.css` 负责 Opus 弹窗、阅览版本选择及中性的原文／更正版本外观，保留赞反效果对比本身的语义。操作台使用细边框次要按钮，发送使用深色实底；禁用按钮采用浅暖灰底、低对比细实线边框和灰色文字，保持原尺寸且无悬停高亮；已阅确认通过 `data-reading-confirm-action="read"` 显示绿色勾选。差异筛选、前后跳转及消息选择在 `shared.css` 中共用结构，颜色跟随各风格变量。

Opus 的页面、卡片和面板分别使用 `#f6f3ec`、`#fffdf8`、`#efebe2`；正文、次级文字和弱提示分别使用 `#1f1d1a`、`#5e5a52`、`#6f685e`。弱提示也必须在面板底色上清楚可读，不能通过额外降低透明度弱化正文。独立介绍页的备用变量与应用保持一致。

| 状态 | 文字 | 背景 | 使用位置 |
| --- | --- | --- | --- |
| 提示／引用 | `#2f4a8a` | `#e8ecf5` | 阅读、引用、信息提示 |
| 成功／赞同 | `#2e6b4f` | `#eaf0e6` | 收入、赞同、仲裁统计 |
| 警示／待处理 | `#8a6320` | `#f5edda` | 登录原因、待分配、结算提示 |
| 错误／反对 | `#aa332b` | `#f8e9e4` | 登录与注册错误、反对、通知失败 |

旧颜色变量也映射到这组暖纸配色，不能保留深色提示底、荧光绿或鲜橙底。浮动同步和手势提示使用不透明卡片底，防止与背后正文叠字。独立记录面板的操作按钮使用 `.record-action`；禁用样式覆盖记录面板、通知和独立 dialog/tooltip，已阅绿色勾选保留。版本选择及通知分类悬停时保留选中配色。检查时同时核对常态、悬停、选中、禁用、错误和移动端；普通可读文字与实际底色的对比度至少为 4.5:1，禁用控件与纯装饰除外。

影响与状态窗口、追溯阅读及费用说明中的普通元信息使用暖灰；旧 slate 文字与分隔线变量归入 `--text-muted/secondary` 和 `--border-default`，蓝色保留给链接、未阅提示等状态。发送条使用不透明 `--surface-card`，与正文输入区相连；下方消息关联和 `.workbench-record-section` 历史记录区延续同一纸色。操作日志时间文字通过 `.operation-log-meta` 指定灰色，避免叠加透明度。排行榜标签、过滤器及记录展开按钮保留选中标识，悬停不覆盖选中颜色；过滤器、贡献点记录保留 dialog 语义，以共用弹窗和禁用控件样式。

视图工具栏的导出、跳转、主页过滤、过滤和对比统一使用 `.workbench-toolbar-action`：常态为次要按钮纸色，悬停统一暖灰底；过滤已启用或面板展开只加强边框与文字，不切换另一种底色。

自动登录入口等待其他模态窗关闭，不限制合法的详情嵌套。操作台问号和档位说明通过 `AboutLink` 在介绍面板定位到对应章节，保留工作台草稿、历史与滚动。三种风格的文档共用宽屏双侧导航和窄屏折叠目录，嵌入时隐藏内层顶栏，外层仅保留文档标题，不显示关闭按钮；可按 Esc 或通过浏览器历史返回，打开时焦点进入文档。题字只在 1440px 以上的外侧留白中淡显。同页章节同步滚动；外层浏览器历史在前进、后退时主动同步内嵌文档与阅读位置。
